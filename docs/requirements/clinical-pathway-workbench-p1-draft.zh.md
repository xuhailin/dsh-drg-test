# P1：EMR 共享定义与结构化参考稿

[English](clinical-pathway-workbench-p1-draft.md) | 中文

状态：2026-10-27 P1 实现与限定独立修正复核已完成，待用户业务验收。见[总览](clinical-pathway-workbench-roadmap.zh.md)与[共享数据要求](clinical-pathway-workbench-model.zh.md)。

## 摘要

医生在 DSH 建立新参考任务或绑定具体定义的修订任务，查看可恢复的结构稿、差异和缺口。临床正文采用 EMR 拥有的共享定义，DSH 使用同版数据做轻量预览与后续 AI（人工智能）修改；完整手工编辑由 P2 的 EMR 组件承担。

<a id="scope"></a>
## 任务与范围

结果是医生能识别、恢复和核对的结构化参考稿，不依赖完整编辑器或 AI 才能建立任务。DSH 提供选择对象、展开详情、查看差异／依据／问题及进入 EMR 的入口；不建设临床字段表单、阶段排期、组包或整方编辑器。

本 PRD 包含 EMR 共享定义的提取与双方消费要求、DSH 参考稿保存和轻量展示。共享定义是路径领域的必要内容，不新增通用表单／状态平台；不搬运 Angular 组件、临床仓储或医院保存入口到 DSH。医院草案、正式编号、业务升版与写入仍不在范围。

<a id="requirements"></a>
## 共享定义与操作归属

临床字段与结构规则由 EMR 共享定义拥有；DSH 拥有参考任务、基线、参考修订、提案记录、锁定及统一参考提交。P2 的 EMR 工作副本和 P4 的 AI 提案都向同一参考提交能力交付候选变更，不形成第二个已保存正本。具体数据要求统一见 M-00～13。

| ID | 必须可观察的行为 | 归属 |
| --- | --- | --- |
| P1-01 | 以 EMR 当前路径定义字段与枚举提取可序列化的共享定义，包含头／科室、诊断／准入、阶段、三类工作、容器、整方和分支。双方消费同一可识别版本；不能手写一套 DSH 临床结构后把映射留到交付末尾。 | EMR 定义；双方消费 |
| P1-02 | 共享数据与 Angular 类实例、选中状态、患者执行、审核流程及医院 HTTP 分离。已有规范化器的缺省、显示前缀、枚举反转和字段丢失必须核对；不能通过默认值把未知临床内容补成已知。 | EMR 共享定义 |
| P1-03 | 来源正文、参考内容和 AI 辅助记录分别归位；原始来源保留，正文不重复保存第二套临床字段。共享定义支持未入库对象及稳定本地引用，不把本地 ID、参考修订写进医院业务 ID／版本字段。 | M-00～02、10 |
| P1-04 | 进入任务复用已知目标与获准范围；新建没有医院身份，修订绑定具体定义／系列／版本／状态。选择和读取沿用既有三工具，范围切换不重标旧证据。 | DSH；M-01 |
| P1-05 | 轻量预览按阶段与类别呈现多行临床内容，可展开组包／整方／分支关系、选择稳定对象并查看全部适用字段、差异、缺口与只读 JSON。轻量只减少操作界面，不删除结构或压成每日一张药品卡。 | DSH；M-03～11 |
| P1-06 | 保存与恢复同一参考修订、基线、辅助记录和锁定；统一参考提交按当前原值／依赖／范围／引用／锁核验，失败原子保留旧稿，重试不重复，撤回不覆盖独立修改。 | DSH；M-09、11、13 |
| P1-07 | EMR 参考编辑产生的候选与 AI 提案都提交到该参考任务；预览、报告和对话刷新到实际已保存修订。EMR 不可用时 DSH 仍可查看保存内容及处理已支持的 AI 操作，完整手工编辑入口明确不可用。 | 双方；M-13 |
| P1-08 | 共享定义版本不支持时拒绝消费／提交并保留旧稿。支持版本中的来源未读全、字典未匹配和参数未知必须无损显示，可查看、选择、讨论并带限制交付；只阻断依赖缺失信息的具体变换，不能丢字段、降级结构或补默认值。 | 双方；M-00、10 |

<a id="dependencies"></a>
## 依赖与数据前置

EMR 的现有模型、序列化器及组件是字段依据，不是已经存在的共享包。其定义混有运行时类型、数字业务身份及执行状态；提取时必须闭合未入库引用、未知值和完整字段表达。打包与分发方式留实施设计，但共享正本、版本标识、双方可消费性与必需结构校验不可后置。

已部署读取器与私有 Session 继续复用；临床字典／模板不完整时可用显式占位和问题，不假装匹配成功。当前数据权限不因 EMR 登录或打开编辑器扩大，临床资料与业务验收前置仍按总览 Q2／Q3。

<a id="acceptance"></a>
## 验收场景

先验共享数据和私有参考任务；组件实际加载在 P2-A 验收，完整手工编辑在 P2-B 验收。P1 不反向依赖 P2 完成才可交付。

| 场景 | 可观察通过条件 |
| --- | --- |
| 成功：双方消费同一数据 | 一份含头／准入、bundle→group→single、整方、阶段前驱与分支的样本通过双方共享定义读取／结构校验；临床字段、枚举、关系、来源原值均保留，无第二份字段映射表。 |
| 成功：新建与修订 | 分别建立无医院身份的新参考和确切版本修订，轻量预览／JSON／差异对应同一修订；无需先打开 EMR 或生成长文。 |
| 边界：未入库对象与缺口 | 多个无医院 ID 的阶段／药味仍有不同本地身份，前驱和辅助记录可解析；0、未知、未读全、code／名称区别不被归一化丢失。 |
| 边界：轻预览与 EMR 不可用 | DSH 可展开全结构和问题，选择同名项目之一不串目标；没有手工临床字段表单。EMR 不可用不丢参考稿，也不阻断已有支持的 AI 提交能力。 |
| 失败：旧版本或不完整来源 | 不支持的共享版本拒绝消费并保留旧稿；未读部分不变空集合，字典或临床缺口可定位，不给可写入结论。 |
| 失败：冲突与保存／撤回 | 旧值或依赖变化时拒绝覆盖；未受影响剩余提案按 M-09 重核后续采纳。重复提交、保存失败和有依赖撤回均保留一致修订及独立编辑。 |

<a id="stages"></a>
## 分期与后置

P1 先交付 EMR 共享定义、两端数据消费核对、DSH 任务保存／恢复及轻量预览，形成可检查产物。P2-A 随后证明单路径组件可直接展示同一参考载荷；P2-B 提供完整手工编辑。P4 提供 AI 操作，P5 提供固定修订交接，均沿用 P1 的参考提交与共享版本。

DSH 完整表单、拖拽编辑和复制一套 EMR 编辑器不在后续补齐清单；这是已确认的界面归属。共享包名、通信传输方式和文件布局留实施设计，不以此扩为通用平台。
