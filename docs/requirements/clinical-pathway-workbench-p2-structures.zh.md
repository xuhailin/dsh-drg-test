# P2：EMR 单路径组件与完整参考编辑

[English](clinical-pathway-workbench-p2-structures.md) | 中文

状态：2026-10-27 按用户确认的界面归属修订；依赖 P1，分 P2-A 参考预览与 P2-B 完整手工编辑。见[总览](clinical-pathway-workbench-roadmap.zh.md)与[共享数据要求](clinical-pathway-workbench-model.zh.md)。

## 摘要

医生在 EMR 的业务上下文中，用同一个单路径组件查看或完整编辑 DSH 参考稿，可由管理页、弹窗或抽屉承载。组件接收 EMR 共享定义数据，加载与提交由宿主提供；参考编辑保存到同一 DSH 参考修订，医院业务维护仍使用原有业务流程。

<a id="scope"></a>
## 医生任务与范围

P2-A 的独立结果是未入医院库的参考稿可以在 EMR 单路径组件中准确预览；P2-B 的结果是完整手工维护头、科室、诊断／准入、阶段、全部项目及复杂关系后，提交为同一任务的新参考修订。组件可独立于管理列表使用，不要求建设脱离 EMR 的独立预览产品。

全部临床表单和复杂编辑界面归 emr-app；DSH 的轻量表只用于查看、选择和 AI 入口。P2 包含必要的宿主连接、参考模式与现有业务模式分离；不包含新医院草案、正式编码、医院保存／审核接口改造、患者执行、通用微前端平台、自动排期或无限嵌套。

<a id="requirements"></a>
## 组件解耦与编辑行为

现有 `ClinicalPathwayComponent` 已有 viewMode 并供审核复用，但内部构造临床 datasource，按业务 ID 加载，包含保存和审核动作。P2 要求复用并拆清这些职责，不把“组件已导出”视为外部参考稿预览已经可用。

| ID | 必须可观察的行为 | 模型依据 |
| --- | --- | --- |
| P2-01 | 单路径展示／编辑可在无管理列表、无 cpList 筛选与维护路由时加载 P1 同版共享数据。组件实例化与参考预览不能按旧医院 ID 自动重读覆盖传入稿，也不能把无医院 ID 当错误路径。 | M-00～02、13 |
| P2-02 | 同一组件由业务维护宿主或参考宿主提供数据和动作；参考模式只允许参考读取／提交，无医院保存、删除、复制创建、审核、启停等动作。限制落实在可调用能力及事件处理，不能只藏按钮。 | M-11～13 |
| P2-03 | 管理页、弹窗／抽屉共用单路径组件；展示接收快照，不因初始化、切页签或关闭而修改传入稿、应用缺省或更改已保存基线。只读预览与参考编辑明确区分，缺口可见；有未提交编辑时退出／主动切任务须按 M-13 选择继续、明确放弃或提交参考稿后退出，不无提示丢弃。 | M-00、09～13 |
| P2-04 | 完整手工编辑覆盖 M-03～08 的全部适用字段：头与科室、诊断组／准入、阶段、药品／检验／检查／手术、诊疗／护理、组包、整方与关联路径。用表单和既有选择组件处理，临床正文保持 EMR 共享字段。 | M-03～08 |
| P2-05 | 新增、复制、拆分、调整和删除阶段时预览日期基准／区间、项目、前驱／后继、分支、锁定和证据引用；内部复制引用指向新本地对象，外部引用明确处理，失败不留半个变换。 | M-02、05、09 |
| P2-06 | 创建／调整／解开 group 与 bundle 时保留顺序与规则；剂量等单项字段只改目标，共享用法、频次、执行科室、天数、必做、可重复及长临联动全部预览。单选／多选与必做变化列明拟清除或转移值，确认后统一应用并可撤回。 | M-06～07、09 |
| P2-07 | 整方按处方头与多味明细完整编辑，药味不能拍平；阶段关联另一条具体路径并保留目标版本与覆盖。未匹配参数、不可读／越权／循环目标保持限制，不自动借用 EMR 当前账号扩大读取范围。 | M-01、06～08、10 |
| P2-08 | EMR 参考工作副本绑定任务／共享版本／参考修订及当前登录关系，修改提交走 P1 统一参考提交，成功后 DSH 轻预览／AI／报告显示相同修订；失败保留工作副本与旧稿，不能提示已写入医院。 | M-09、11、13 |
| P2-09 | 未提交新对象／已改目标先提交参考稿或放弃相关修改，再传给 AI；未受影响已保存对象可继续选择。AI 采纳与 EMR 手工编辑交错时按 M-09／13 核对冲突，不能最后保存者覆盖。窗口重载、任务／账号切换使旧连接失效；迟到结果不能更新新目标。锁定项及子项在所有编辑入口均受约束。 | M-09、13 |

<a id="cross-day"></a>
## 跨日修改的确认语义

“第 3 天 X 改 Y”命中住院日第 3—4 天共用阶段时，先定位阶段和项目，区分日期基准、同名与组内联动，再让医生选择整阶段或仅第 3 天。仅某日时预览拆分后的项目归属、前驱／后继、分支、锁定和证据引用，确认后形成一个参考事务；新药规格／剂量／单位／用法等重新核定。

区间中间单日，如第 2—5 天仅改第 3 天，必须预览第 2 天、第 3 天、第 4—5 天三段，前后未改内容保留。取消或保存失败原稿不变；前驱环、悬空本地引用及非法嵌套不能以确认绕过。P4 的复杂 AI 提案复用这些临床语义，不要求 EMR 窗口运行才能在 DSH 采纳。

<a id="dependencies"></a>
## 数据前置与依赖

P1 的共享定义、未入库引用、结构校验和参考提交是前置；P2 不依赖 P3 统计、P4 AI 或 P5 报告。P2-A 先以确定性参考载荷验组件，P2-B 可用同一参考提交能力验完整手工编辑，因此不存在“等待 AI 才能证明组件”的循环。

宿主连接只传获准参考任务、修订和受限动作，校验来源／窗口／账号与任务关系；不透传通用医院 HTTP 能力或凭据。通信形式留实施设计，必要的身份关联和真实 EMR 集成验证不得用独立示例页代替。临床字典查询也须符合原授权，既有账号复用许可不等于 EMR 所有业务权限都可给助手。

<a id="acceptance"></a>
## 验收场景与分期

P2-A 完成组件解耦与只读参考预览，P2-B 完成所有手工临床操作、统一提交和失败恢复。既有医院维护页与审核只读复用须保留原有职责，不能因参考模式改造改变业务保存语义。

| 场景 | 可观察通过条件 |
| --- | --- |
| A：无管理页预览 | 同一参考载荷在管理页宿主与 EMR 弹窗／抽屉中完整显示，同一组件不依赖列表选中项；无医院 ID、含未知字段的稿也能看，打开／切页签／关闭不改数据或发业务写请求。 |
| A：修订稿不读回旧版 | 参考稿与医院原版本某字段不同，预览显示传入参考值，不按原 ID 覆盖；分段未读显示覆盖而非空集合。 |
| B：基础与完整项目编辑 | 在 EMR 编辑头／科室／诊断／准入及全部单条适用字段，提交后 DSH 同修订显示；没有 DSH 临床表单副本，普通业务维护仍按原流程。 |
| B：复制完整阶段与单日 | 复杂阶段复制有唯一新本地身份及正确引用；第 3—4 天端点和第 2—5 天中间单日修改均只变确认范围，前后内容不丢，取消失败原稿不变。 |
| B：组包与选择联动 | 单项剂量不改其他条，组共享频次显示全部联动；单选／多选及必做变化预览清除／转移，确认与撤回后规则一致，非法嵌套和不兼容成组不通过。 |
| B：整方与关联路径 | 处方头和三味明细的身份、顺序、单位 code／名称完整保留；关联目标版本准确，循环终止、越权不读取，移除关联不删目标。 |
| B：未提交选择与退出 | 新增未提交项目或修改药品后说“这里”，提示先提交／放弃相关修改或继续编辑，不按旧值生成提案；取消退出保留副本，明确放弃不改 DSH 稿，提交失败继续可处理且不走医院保存。 |
| B：交错修改／锁定 | EMR 编辑期间 DSH 采纳 AI 修改，受影响手工提交被拒并显示差异，独立项重核后可提交；锁定子项不能绕过，撤回保留其他独立编辑。 |
| A／B：断连、账号与重复 | 断连不显示已提交，重载重新绑定；切任务／账号后旧响应不能绘制或提交。重复同一提交只生成一个修订，未知结果先核对状态，不改走医院保存。 |
| A／B：真实宿主与旧入口 | 在实际 EMR 宿主验证授权、参考加载与保存隔离；同时验证原维护页和审核只读入口，独立壳演示不能代替。 |

独立预览网站、独立登录产品、PDF／Word 编辑、拖拽排期与医院写回后置；完整结构编辑仍是 P2-B 必须交付的能力。

<a id="dev-note"></a>
## 开发备注

P2 在 P1 真实数据验证与代码推送后开始实施，先拆无路由单路径模块并接入共享载荷只读展示，再交付 P2-B 完整参考编辑。医院数据写入和后端变更仍不在范围。
