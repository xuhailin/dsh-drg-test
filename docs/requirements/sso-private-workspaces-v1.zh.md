## 概要

通过统一公司 SSO 入口访问现有 DSH Web，为每个账号保留私有聊天、文件、终端和工具交互。当前交付包含 Docker 代码、使用 mock 身份／模型服务的本地验证，以及公司 SSO 注册清单。首个真实模型提供方使用 DeepSeek；sub2api 和独立的 DRG 原型暂不纳入。

<a id="confirmed-scope"></a>
## 已确认范围

用户选择公司 stable SSO、多人登录且各自私有聊天、保留 DSH 工具能力，以及公司内网 Linux 部署。随后，用户授权在选择服务器和域名前完成 Docker 实现与本地验证。首批交付不依赖真实 SSO 应用注册；本地 mock 提供方用于验证登录流程。

用户确认公司 SSO 不支持授权码流程，并选择兼容现有 EMR 登录方式的 implicit 流程。实现保留授权码作为默认选项，并允许此公司应用使用仅返回 ID token 的 implicit 响应；公司提供方启用授权码流程不是前置条件。

用户要求访问后直接进入首页，省去入口再次点击登录，并改善状态和失败页面。打开统一入口会自动继续登录，或恢复当前账号的工作区。显式退出后必须保留确认状态，不能通过仍有效的公司 SSO 会话立即重新登录。

每人需要私有工作区、执行权限和工具交互。本次范围包含现有聊天界面及其支持的命令、文件、终端、审批和子 Agent 流程。平台专属或外部工具是否可用，取决于部署镜像及集成；保留工具不表示所有桌面能力都能在 Linux 使用。

用户选择第一版使用服务端持久化私有数据卷。将聊天迁入 EMR PostgreSQL 数据库或新增 OceanBase 不属于本次交付。验收必须验证重启后保留历史、在另一个浏览器重新登录后看到相同历史，以及跨账号访问被拒绝。用户已批准使用私有 GitLab 项目 [xu.hailin/dsh-drg-test](http://git.sy/xu.hailin/dsh-drg-test)运行 CI 和发布。公司镜像仓库的匿名发起上传探测成功且已取消后，用户选择 CI 仅构建镜像、不上传。服务器和公司域名仍延后选择。

试用不连接真实患者记录、不实现 DRG 规则、不修改 emr-app，也不提供公开匿名代码执行。用户间共享工作区或聊天不在首版范围内。

<a id="current-implementation"></a>
## 当前实现

可选的 [hosted-workspaces 组合包](../../packages/experimental/hosted-workspaces/README.zh.md)实现 OIDC 登录、持久化账号与浏览器会话、个人 Docker 运行实例分配、经认证的 HTTP／WebSocket 路由，以及受限制的共享 Key 模型访问。[Docker 试用指南](../user/guide/hosted-workspaces.zh.md)拥有本地命令和准确的 SSO 注册清单。

未认证的入口 `GET /` 通过 HTTP 303 发起 SSO；有效入口会话进入自己的工作区。匿名个人 `/` 和 `/index.html` 请求返回 `/auth/login`，不将旧 origin 绑定为登录目标。经过验证的当前身份决定个人 origin。显式目标校验和跨账号 API 拒绝仍然生效。

每个个人容器使用既有 Web profile 和其中的 [owner Peer](../../packages/client/connection/src/rpc-host.ts)。该 owner 仅控制一个账号的运行实例。独立 home 数据卷和 Docker 执行环境提供用户隔离；会话权限或不同工作目录本身不能提供这种隔离。

仓库提供 Docker 镜像、独立 gateway profile，以及包含 mock OIDC 和模型服务的本地 Compose 覆盖配置。这些产物支持在没有公司服务器或 API Key 的情况下本地运行。产物存在不表示完整 Docker／浏览器／工具流程或公司部署已经通过验收。

<a id="architecture"></a>
## 架构

实现采用统一 SSO 网关和每账号一个个人 DSH 容器。一个容器服务该账号的聊天和浏览器会话。退出登录会保留容器、私有卷和后台工作；未实现自动空闲停止。

| 组件 | 职责 |
| --- | --- |
| SSO 网关 | 使用独立注册的 OIDC 应用认证，维护浏览器会话，只将 HTTP 和 WebSocket 流量转发到当前认证用户的运行实例。 |
| 运行实例管理器 | 将稳定认证身份映射到私有容器和数据卷，验证或启动运行实例，并应用容器限制；用户容器不可访问其 Docker 控制权限。 |
| 用户 DSH 实例 | 使用私有数据目录、Agent 配置、工作区、进程及工具交互启动既有 Web profile；本地 owner 的作用范围限制在该用户容器内。 |
| 模型网关 | 在用户容器之外保存上游 DeepSeek Key，验证受限的实例凭据，限制可用模型、请求路径及每用户用量。 |

所有 DSH 应用均通过命名 profile 启动。仓库镜像使用 `gateway` 启动通过 profile 加载的网关插件，使用 `web` 启动个人运行实例。实现不新增包级可执行入口，也不修改 agent loop（智能体循环）。

<a id="identity-and-private-data"></a>
## 身份与私有数据

通过已验证的 issuer 和 subject 解析内部用户身份。显示名、浏览器提供的工号、URL 参数或转发的客户端请求头，不能选择其他用户的运行实例。同一身份重复登录恢复原私有数据；不同 issuer 下相同的 subject 保持区分。

两种已配置的登录流程均须先验证已签名的 ID token，才能创建会话。implicit 模式通过同源 POST 接收 fragment，由网关验证签名、issuer、audience、有效期、nonce 和绑定浏览器的 state。DSH 不需要 EMR 业务 access token，不使用密码授权，也不将 SSO token 保存到 localStorage。

已有有效会话时，不带响应字段的 implicit 回调会经统一入口恢复。携带 state 的 fragment 仍是真实认证响应，不能通过恢复路径绕过验证。DRG Agent 状态页在验证和交接期间显示加载状态，区分登录和工作区失败，并提供相应重试操作。失败诊断只包含操作和安全的分类代码，不输出原始错误消息或凭据值。

网关拥有身份与实例映射、浏览器会话记录。每个实例拥有自己的 DSH_HOME、DSH_AGENTS_HOME、聊天、附件、设置、用户安装的插件、工作区和终端状态。实例管理器拥有数据卷分配和容器生命周期；私有卷不得挂载到其他用户容器。

index 响应、API、上传、下载、日志导出、预览及 WebSocket 升级采用相同授权。个人运行实例端口不向宿主机发布。网关使用不带路径的入口 origin 及每账号子域名；公司反向代理须保留 Host 并支持升级，详见[部署指南](../user/guide/hosted-workspaces.zh.md#company-services)。

浏览器存储与可执行页面内容使用每账号独立的 origin，包括多个账号使用同一浏览器的情况。网关验证认证身份拥有所请求的 origin。SSO cookie 和上游登录 token 不转发到个人 DSH 容器。

退出或到期使相应浏览器会话失效，并关闭其已建立的流；不会删除私有文件或授权另一身份。当前的应用内退出会保留后台工具和提供方的全局 SSO 会话；不实现提供方退出或任务取消。

<a id="execution-and-credentials"></a>
## 执行与凭据

每个个人容器获得自己的持久化 home 数据卷和应用镜像。不使用宿主 PID 或网络命名空间、特权模式、Docker socket、宿主根目录挂载或控制面凭据。Docker 配置强制执行内存、CPU、PID 和临时存储限制。部署验收须验证网络／防火墙配置阻止访问其他用户运行实例及宿主控制面，同时允许已配置的集成和模型网关。

当前实现不为持久化 home 数据卷提供每账号磁盘硬配额。Linux 共享部署需要强制执行文件系统／项目配额或其他经验证的存储限制，并具备磁盘写满恢复和备份流程。数据卷隔离不提供磁盘配额。

在容器内保留 DSH 既有逐调用沙箱和审批行为。容器负责用户间隔离；不同工作目录或 DSH 沙箱模式不能替代它。审批请求、回答、终端流及子 Agent 保持在所属运行实例内。

真实 DeepSeek Key 不得进入个人容器的环境变量、凭据文件、日志、镜像或挂载。保留命令和文件工具的用户可以检查自己的运行环境。个人运行实例只获得自己的受限模型网关凭据；提取该凭据不能获得其他用户的数据、额度或管理操作。共享 Key 代理仅接受流式 Messages 请求，拒绝 Files 操作和上游文件引用；图片内联回退仍需端到端验证。

<a id="acceptance"></a>
## 验收

首批交付使用合成数据和 mock 外部身份／模型服务，验证本地 Docker 组合，同时执行真实 DSH 运行实例和工具。公司验收还通过计划采用的入口执行真实 SSO 和 DeepSeek 流程。两个阶段均保留下列隔离与失败要求；已执行结果在下方单独记录。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 没有 DSH 会话时打开入口，再携有效会话访问。 | 自动发起登录；有效会话恢复当前账号自己的工作区，无需再次点击入口。 |
| 打开匿名或已过期的个人首页书签，再认证为另一个账号。 | 经过验证的当前账号选择自己的个人 origin；旧主机不能选择运行实例或暴露其数据。 |
| 携有效会话重新打开空 implicit 回调，或提交携带真实 state 的 fragment。 | 空回调经统一入口恢复；真实响应仍须通过正常的 token 和登录流程验证。 |
| 用户 A、B 同时登录。 | 各自只能看到自己的历史、工作区、设置、下载和实时工具输出；直接请求对方资源被拒绝。 |
| A 使用文件和命令工具发起绝对路径、路径越界、符号链接及网络请求。 | 不能访问 B 的数据卷、实例、进程资料或宿主控制面；A 仍可读写自己环境内获准的文件。 |
| 双方都有待审批、提问、终端或子 Agent。 | 交互只到达所属用户；重放对方交互标识不能批准或控制它。 |
| A 在 WebSocket 已连接时退出、切换账号或会话到期。 | 相应连接失去访问权；缓存 UI 不向下一账号暴露 A 的资料；B 的独立会话仍可用。 |
| 容器或服务器重启。 | 从所属数据卷恢复身份映射、私有聊天及文件；另一身份不能认领它们。 |
| A 检查环境变量、凭据文件或模型错误。 | 不出现上游 DeepSeek Key；最多能看到 A 自己的受限代理凭据；额度仍在 A 的实例之外强制执行。 |
| A 在后台工具运行时退出。 | 浏览器访问权被撤销，工具仍限制在 A 的运行实例内，保留工作说明页等待用户显式登录。 |
| implicit ID token 被伪造、已到期、audience 不符或被重放。 | 认证失败，不创建浏览器会话，也不选择运行实例。 |
| SSO、容器启动、模型请求或资源分配失败。 | 相关操作明确报错并提供恢复操作，不转向其他运行实例、不声称成功、不删除私有数据，也不在诊断中输出凭据。 |

本地验收要求使用两个 mock 身份，经真实 DSH 运行实例完成流式聊天和真实文件／命令工具结果，并观察隔离、持久化、退出及失败结果。单元检查和仅启动容器不能满足该阶段。公司验收还须经过计划采用的入口，完成真实 SSO 和真实 DeepSeek 流式聊天；两个阶段都需要独立用户验收。

<a id="dependencies-and-verification"></a>
## 依赖与验证

Docker 是当前实现目标；Kubernetes 不在本次交付范围内。具体 Linux 主机、公司入口域名／TLS、网络／防火墙控制、持久存储配额及运维恢复均延后确定。这些选择均不阻塞本地 mock 组合。

公司集成需要管理员为所选流程分配的 OIDC 客户端、匹配的发现／JWKS 元数据，以及准确的入口 `/auth/callback`；个人子域名无需注册回调。用户确认的公司路径使用不需要客户端密钥的 implicit 登录。支持授权码的提供方仍可选择授权码流程。网关不调用提供方退出。[注册清单](../user/guide/hosted-workspaces.zh.md#sso-registration)拥有管理员设置及各流程的密钥要求。完整公司集成和部署验收仍待完成。
