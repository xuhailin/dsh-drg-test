# 临床路径助手 V1

[English](clinical-pathway-assistant-v1.md) | 中文

状态：截至 2026-10-26，只读工具及参考流程已本地部署，合成技术验证、获准开发读取及真实入口的管理核对参考稿演示通过，临床质量及独立用户验收待完成。`clinical-pathway-analysis` 支持路径分析、新建和修订参考方案；业务写入仍留到后续独立接入。

## 摘要

临床医生和路径管理人员可以让助手分析某条路径，或生成新路径／已有路径调整的参考方案。三个工具读取获准开发数据：`pathway_read`、`history_query`、`case_read`，返回依据、人群口径、资料缺口和供人工判断的建议。代码和组合归本项目，不要求改动 EMR 前端、后端、接口或业务库结构；取数仍依赖 EMR 的表、关联关系和业务含义。

<a id="scope"></a>
## 目标与范围

交付结果是可解释的分析或可编辑参考文档。生成方案不创建医院路径、不分配业务版本，也不改变患者诊疗。

| 项目 | 当前要求 |
| --- | --- |
| 分析某条路径 | 定位确切定义／版本，检查历史人群及已记录的执行／变异，以明确分母和证据缺口说明发现。 |
| 生成参考方案 | 支持新路径参考方案或已有定义的修订建议，使用实际资料和获准参考文献，呈现变更时保留原有内容。 |
| 实现归属 | 工具、固定 SQL、分析指令、展示和 Session 记录均在本仓库可选临床路径组合中实现；EMR 源码是解释数据的依据，不是本阶段改造目标。 |
| 数据来源 | 通过服务端持有的只读连接和参数化查询，读取用户指定的 `pg_develop` 开发库；真实读取前核对确切数据库／schema 及获准医院／科室／历史范围。 |
| 脱敏 | 不以新增脱敏服务为前提；经已批准模型通道读取获准分析必需字段，不把患者内容交给公开搜索或写入公开示例。 |
| 产物保存 | 分析输入、引用、参考方案修订和用户编辑保留在私有 DSH Session 或用户要求的本地参考文件中；这些是参考产物，不是医院业务草案。 |

本阶段不包含业务库写入、创建草案、生成业务版本、修改病历、患者入径、开立／执行医嘱、提交审核、发布、实时监控、患者文件夹或新的临床助手中转后端；不要求建设 MCP 基础设施或通用 SQL 工具。用户审阅只修改参考产物，不授予医疗系统写权限。

<a id="flow"></a>
## 使用流程与参考产物

助手按路径／分析主题组织工作，不要求绑定患者会话。用户说明目标、可用路径、科室／人群和时间范围，已有信息直接复用。

1. 分析已有路径时调用 `pathway_read` 定位并读取确切版本；生成新参考方案时先明确目标人群和可比较定义，不假装业务系统已经存在该路径。
2. 调用 `history_query`，明确医院／科室、诊断、时间和可选路径／版本筛选，展示计数对象是去重住院还是路径执行记录。
3. 仅对相关病例调用 `case_read`，按类别和片段有界读取；文书文本缺失或执行／报告来源未支持时保留明确缺口。
4. 输出分析发现或参考方案，包含数据时间、来源标识、样本／覆盖限制、依据、建议改动及需临床判断的问题。
5. 用户可讨论、编辑或请求下一版参考稿；产物明确标为参考方案，不声称已保存到医院系统、已审核或已发布。

| 产物 | 必须包含的信息 |
| --- | --- |
| 路径分析 | 确切路径／版本、人群条件和时间口径、病例／记录数、来源状态分布、变异依据、覆盖及发现；系统标记完成与临床任务实际完成分开。 |
| 新参考方案 | 目标人群及排除条件、来源资料、候选阶段／时间窗／任务／分支、理由和引用、不确定项及人工复核问题；不支持的诊疗要求留待确认。 |
| 修订参考 | 基线定义、修改前后内容、理由和依据、保留的未改部分、参考稿修订及未决问题；v1／v2 等参考稿标识不是业务系统版本。 |

历史频率属于观察结果，不等于临床规范；指南及院内要求需要实际可查的参考资料。展示读取时间和来源修订，不把不同工具调用表示为同一不可变数据库快照。

<a id="tools"></a>
## 三个只读工具

下表是本阶段已实现的全部 DSH 原生业务工具；需显式启用读取组合并通过来源检查，本地部署已启用读取组合。表、字段和关联细节统一放在[实施计划](clinical-pathway-assistant-v1-implementation.zh.md#tables)。

| 工具 | 输入 | 可观察结果 |
| --- | --- | --- |
| `pathway_read` | 有界搜索或确切版本 ID，可选系列／版本及所需定义部分；医院／科室权限由可信配置提供。 | 指定版本定义、诊断／准入条件、有序节点、分支、项目及支持的关联内容，附身份／状态和缺失组成。 |
| `history_query` | 获准范围、明确的入院／出院／入径时间口径、时间窗、诊断条件、可选路径／版本和执行状态、列表／汇总选择及有界分页。 | 历史住院队列或定义明确的汇总，分别列住院／执行次数、实际版本关联、已登记原因、来源状态、分页／截断及缺口。 |
| `case_read` | 获准住院 ID、资料类别／引用及有界分页／片段。 | 就诊、诊断、医嘱、已落地可读文书文本、原始来源状态／时间及不可读／未支持覆盖。 |

工具代码选择固定 SQL 和允许列，模型参数不能成为 SQL 片段、标识符、凭据或任意数据库地址。默认要求专用 SELECT-only 账号；获准开发模式复用现有账号，仍由固定 SQL 与强制 READ ONLY 事务独立于提示词约束源数据不变。本阶段没有写入工具。

<a id="requirements"></a>
## 行为需求

以下要求同时约束路径分析与参考方案生成，物理 schema 核验和临床证据解释分别验证。

| ID | 要求 |
| --- | --- |
| CPA-01 | 区分分析、新参考和修订参考；已有路径工作绑定确切定义／版本，切换目标不能把其他目标的证据作为当前依据。 |
| CPA-02 | 仅通过 `clinical-pathway-analysis` 提供三个作用域读取工具；采用固定参数化 SQL、只读事务、明确医院范围、限额、超时和取消，不暴露任意 SQL 或业务写能力。默认使用专用只读凭据；用户已明确确认开发联调可复用现有账号，并保持强制只读事务。 |
| CPA-03 | 启用读取前核验实际开发数据库及必要表／列；映射缺失或不兼容时可见失败，不改查其他来源或编造记录。 |
| CPA-04 | 历史队列按明确筛选包含符合条件的未入径、已完成和退出病例，不将仅在院权限或当前入径标志当历史成员依据。没有对应执行记录或所选时间的病例不属于该执行队列；未入径比较队列另按入院／出院窗口定义并另报分母。 |
| CPA-05 | 去重住院数与执行记录数分开，保留诊断和执行状态；每项统计说明分子／分母、时间口径、抽样及缺失处理。 |
| CPA-06 | 证据关联当时实际使用的路径定义，不拿现行发布版本替代历史基线，也不只凭重载字段名称拼接 ID。 |
| CPA-07 | 按来源含义解释医嘱、收费、记录存在和系统完成标志，任何一项都不能独自证明全部临床任务已执行。 |
| CPA-08 | 只返回实际读取的内容并附引用／时间；`record_text` 缺失表示文本不可读，不是病历不存在；未支持的检验／检查／执行来源保持未支持。 |
| CPA-09 | 区分观察、计算、参考依据、推断和改动建议；重要数据结论引用可访问证据，不支持的临床要求保留为问题。 |
| CPA-10 | 模型可见查询结果和参考稿修订留在私有 Session，刷新后可还原分析；查询完成时间不代表跨工具／分页共享快照。 |
| CPA-11 | 产物明确为参考分析／方案，保留修订比较和用户编辑，不声称已发生医院草案、业务升版、写入、审核或发布。 |
| CPA-12 | 失败保留已有参考产物，报告不可用／部分／未知覆盖；访问、取消、模型生成或参考产物保存都不修改业务表，也不自动降级为写入。 |

<a id="acceptance"></a>
## 验收场景

技术验证先使用合成数据，真实开发读取和独立用户验收需要确切获准数据范围；源码调查不代表运行时已经支持。

| 场景 | 可观察通过条件 |
| --- | --- |
| 分析指定版本 | 展示正确的定义、筛选、证据和覆盖，比较实际历史版本，不混入其他路径或版本。 |
| 生成新参考方案 | 使用目标人群及符合条件的未入径历史，生成明确标记的参考稿，不创建任何路径记录。 |
| 提出修订建议 | 展示修改前后及用户编辑，医院定义和发布状态完全不变。 |
| 同一次住院多诊断／多次执行 | 关联后不放大病例分母，住院数和执行次数分别标识，不把非路径治疗默认为入径。 |
| 重载 ID 与原因类型 | 按已核关联解释执行、节点、医嘱和审核退回，不因错误连接伪造任务证据。 |
| 文本缺失或来源未支持 | 显示不可读／不可用／未支持类别和部分覆盖，不声称完整读完病历或判定临床完成。 |
| 非法范围、SQL 输入或超限查询 | 拒绝越权和任意 SQL，执行配置限额／取消，并证明连接不能修改源数据。 |
| 刷新、失败或数据不完整 | 输入与参考稿可还原，显示读取时间和部分范围，不把多次读取宣称为同一快照。 |
| 缺少合适临床参考资料 | 呈现证据局限和复核问题，不把历史常见行为直接变成获准诊疗标准。 |

<a id="future"></a>
## 未来写入接入

写回可作为后续独立评审能力接入。参考产物保留目标／基线身份、参考稿修订、差异、证据及数据截止时间，供未来交接；现在不建设确认令牌、提交回执或业务版本子系统。未来写工具先明确用户对具体内容的确认、权限、新草案／版本语义、冲突重试及原系统审核发布流程，这些接口是否具备不阻塞当前只读阶段。

<a id="dependencies"></a>
## 依赖与状态

范围已收敛，剩余前置项是来源访问和数据解释证据，不是新增 EMR 功能。

| 依赖 | 所需证据 |
| --- | --- |
| 只读目标与访问 | 确切开发数据库／schema、连接归属、获准医院／科室／历史范围、已批准模型通道和有界读取配置；凭据留服务端。 |
| 物理映射 | 按目标 schema 核对计划中的源码表／列／关联清单，包含 nullable 状态、医院过滤、可选整方表及文书文本覆盖。 |
| 统计与参考依据 | 确认科室／时间／诊断口径及来源状态定义，指定获准指南／院内资料和方案质量的临床复核者。 |
| 验收 | 指定典型路径分析／新方案任务、合成 fixture、获准开发样本和能说明预期／实际／通过理由的用户。 |

只读核对开发库目录及 19 张来源表的 287 个字段已通过，未修改源库。提供方／HTTP 客户端的有界读取及本地真实入口的定义／历史查询通过，真实模型已生成并修订管理核对参考稿。提供方报告仅保留计数和覆盖，不含患者标识或正文；[实施计划](clinical-pathway-assistant-v1-implementation.zh.md)列明数据清单及确切验证范围。新建诊疗路径方案、模型调用 `case_read`、临床质量及独立用户验收仍待验证。

## 开发备注

[临床路径 preset](../../deploy/hosted-workspaces/clinical-pathway.preset.yml)默认分析提供资料，显式只读组合增加三个工具；既有[医保核查需求](clinical-result-viewer-v1.zh.md)保持自己的患者范围和流程。用户已选择测试科室和最近一年，并明确确认开发联调复用现有账号、保持固定 SQL 与强制只读事务。本地部署及真实模型演示使用该获准范围和既有模型通道；未写源库或修改角色权限，等待用户验收。
