# P4：AI 制定与受控修改

[English](clinical-pathway-workbench-p4-assistance.md) | 中文

状态：2026-10-27 按 DSH AI／EMR 完整手工编辑分工修订，细节待审阅；P4-A 依赖 P1 及实际使用的 P3-A，P4-B 先完成对应 P2-B 临床语义验收，运行时不依赖 EMR 窗口在线。参见[总览](clinical-pathway-workbench-roadmap.zh.md)与[共享模型](clinical-pathway-workbench-model.zh.md)。

## 摘要

医生能按科室和诊断制定结构化新参考方案，或对确切版本提出修订；选中项目说“这里怎么改”，一句话提出多项调整，也可把科室讨论转为修改清单。系统先定位、列影响与依据，再让医生逐项或批量采纳、暂缓、撤回，保留人工修改与锁定。

## 医生任务与范围

输入是目标人群、已有参考稿／确切来源版本、实际可用临床资料与历史观察。输出是结构化新方案提案或可执行的局部变更提案，先供医生审阅；临床参数无依据时产物保留明确缺口。

包含自然语言定位、结构化制定、多项修改与依赖、依据查看、影响预览、采纳／暂缓／撤回和讨论清单。排除自动批准治疗、替医生补关键临床判断、暗中解锁／覆盖、医院业务保存、自动审核发布、广泛联网收集患者资料和独立生成写入 DTO。

<a id="requirements"></a>
## 行为需求与操作归属

P4 在 DSH 拥有意图解释、修改提案和采纳界面；P1 统一参考提交并保存 EMR 共享临床数据，P2 拥有完整手工组件及复杂语义验收，P3 提供候选，P5 消费确切修订。DSH 不补临床字段表单，AI 改前范围确认与采纳控件仍在 DSH。

| ID | 必须可观察的行为 | 模型依据 |
| --- | --- | --- |
| P4-01 | 新建任务生成有头、诊断／准入、阶段、项目及适用关联的结构化候选，缺内容可显式未知；修订任务只提与目标相关的差异，保留未改内容与确切基线。解释文字不能替代结构。 | M-01～08、10 |
| P4-02 | “这里”绑定 DSH 轻预览或已授权 EMR 宿主记录的对象身份、字段、共享版本与参考修订，发送时可见目标；EMR 选择传递按 M-13 校验，任务／账号切换后旧选择失效。未提交新对象或已改目标／依赖须先提交参考稿或明确放弃相关修改，也可继续编辑；不把工作副本当已保存稿传给 AI。选中对象已经删除、变更或同名匹配多项时先定位确认，不重新按名称猜。 | M-02、09、11 |
| P4-03 | 一句话多修改拆成可定位条目，展示改前／改后、日期／阶段／容器影响、理由、来源及未决参数。独立条目可分别采纳／暂缓；有关联依赖的条目显示不可拆事务及顺序。 | M-05～10 |
| P4-04 | 新方案与修改都先预览，采纳前复核范围、目标修订、锁定及结构有效性；采纳、批量、重试和撤回使用统一事务语义。撤回一项时不抹掉其他独立修改。 | M-09 |
| P4-05 | 第 3 天命中跨日阶段时按 M-05／P2-B 已验临床语义展示范围选择与引用预览；P4-A 无复杂变换能力时给出准确定位和后置说明，不生成可采纳的假拆分。 | M-05、09 |
| P4-06 | 药品替换按目标规格／剂量／单位／用法等逐项复核；没有依据则保留待确认。字典未匹配、参数未知、来源未读全分别显示，不把名字替换成功称作完整方案。 | M-02、06、10 |
| P4-07 | 每项重要临床要求或历史结论可查看实际依据／片段与适用范围；区分观察、计算、指南／规范、人工意见及推断。历史候选转方案必须另行采纳，不能直接设成标准或必做。 | M-10 |
| P4-08 | 将科室讨论输入转换成带原文引用的修改清单，区分共识、建议、冲突和未决项；不把说话人意见当指南。存在互相矛盾的修改时保留冲突、请医生选择，不能自动合成。 | M-09～10 |
| P4-09 | 问题集中显示为少量可定位项，每项说明所需判断及阻断范围；可继续处理独立变更。已有明确目标和权限不重复追问，模型不能因为缺一个参数就重做整条路径。 | M-09～10 |
| P4-10 | 模型失败、取消或输出不合结构要求时保留现有稿与人工编辑，失败提案不应用；输入、选择、证据和结果留在私有可恢复记录。重新生成从当前修订出发，过时提案不自动重放；未受影响的剩余条目按 M-09 重核并更新预览基准后可继续逐项采纳。 | M-09～11 |

<a id="dependencies"></a>
## 数据前置与依赖

P1 提供 EMR 共享定义、参考保存与统一提交；P4-A 对单条项目提案可先验收，完整手工临床编辑在 P2。用历史制定时消费 P3-A 的完整范围与候选；无历史仍可用医生明确提供的目标／资料起草，并标明缺少真实样本。P4-B 对复杂内容先完成对应 P2-B 语义验收，再按共享规则通过 P1 提交；DSH 的 AI 操作不能调用仅浏览器可用的 EMR 类或依赖活动编辑窗口。模型结构输出必须符合 EMR 同版共享定义，不能先生成 DSH 自有结构再到交付时转换。

临床资料必须实际可读且适用，EMR 当前空的诊疗指南页不能作为来源。模型不能自主寻找凭据、扩科室取数或把患者内容发给公开检索。缺少临床资料时可交付结构完整但临床值待确认的参考稿，不许编造治疗、剂量或阈值；Q2 未落实不能宣称治疗方案质量通过。

<a id="acceptance"></a>
## 验收场景

每个场景同时核对结构稿、变更清单、来源与恢复记录；只观察对话回答不算完成。

| 场景 | 可观察通过条件 |
| --- | --- |
| 成功：新参考与确切版本修订 | 同一获准范围分别完成两任务；新稿为结构化候选，修订只改要求部分，无基线冒认或医院编号，缺依据参数保持问题。 |
| 成功：这里＋多项修改 | 选定同名项目之一，说“这里改频次，另一护理项改必做”；目标身份明确，采纳一项、暂缓一项后当前稿只出现已采纳变更。 |
| 边界：同清单连续采纳 | A、B、C 基于 r1；采纳 A 后重核未受影响的 B，更新预览基准并可采纳，C 仍暂缓，独立人工编辑保留。若 B 目标或依赖已变，只使 B 过时并要求新预览。 |
| 成功：批量与依赖 | 独立变更批量只产生一致的新修订；拆分＋改项目等依赖不能只采纳后半段；重复提交不重复修改。 |
| 边界：跨日与药品替换 | 第 3—4 天共享阶段不自动选范围；确认仅第 3 天后按 P2 变换，新药不继承未经核定参数；P4-A 明确不支持该变换。 |
| 边界：EMR 选择与交错编辑 | EMR 选择准确传入当前任务，DSH 展示同对象后可提案；其间 EMR 手工提交后，AI 只对受影响项判过时，旧连接／选择不能进入新任务。 |
| 边界：未提交的这里 | EMR 新增未提交药品或已修改目标字段时，AI 不对不存在对象或旧值生成可采纳提案；先提交／放弃／继续的选择清楚，未受影响已保存项目仍能操作。 |
| 边界：EMR 不可用 | 关闭或断开 EMR 后，DSH 对已支持结构仍能提案、采纳并恢复；完整手工编辑入口显示不可用，不转成另一套字段表单。 |
| 失败：锁定与并发人工修改 | 模型无法改锁定项；生成期间人工修改影响目标、依赖或范围时，使相应旧提案过时，不能覆盖；独立条目按 M-09 重核；刷新后已提交人工编辑／锁定不丢，未提交 EMR 副本不冒充已保存内容。 |
| 边界：讨论冲突与观察 | 相反两条意见保留冲突与引用；高频历史药只进入候选，医生确认前不新增必做或临床阈值。 |
| 失败：模型输出或证据缺失 | 非法嵌套、虚构 code、未读资料不得应用为已验证内容；失败不改稿，缺口可定位，允许独立有依据条目继续。 |
| 边界：撤回后有新编辑 | 撤回一项保留其他修改；有依赖时列范围并要求选择补偿方案，模型不暗中回退整个版本。 |

## 分期与后置

P4-A 跑通简单结构的新建与修订、选择定位、多项提案、依据／问题、逐项／批量／暂缓／撤回，以及简单讨论清单，支撑 M2。可读取复杂内容并解释覆盖，但不对其生成可应用变换。

P4-B 在对应 P2-B 语义验收后完成阶段拆分／复制、容器、整方与分支的受控生成／修订、复杂依赖及讨论冲突。自动规划临床最优方案、无规则历史试走和自动批准不在两期范围。模型或提供方选择、结构输出实现方式和重试次数留实施设计，不以调模型代替验收。

<a id="dev-note"></a>
## 开发备注

临床内容质量验收必须有 Q2 的实际依据和临床负责人；共享版本、EMR 宿主绑定与离线于编辑窗口的 AI 运行要单独验证，独立需求 review 均不能替代。
