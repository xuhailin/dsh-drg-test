# 临床路径助手：分期 PRD 与跨仓归属

[English](clinical-pathway-workbench-roadmap.md) | 中文

状态：2026-10-27 P1 的 EMR 共享定义、DSH 参考稿保存与轻量预览已实现并完成限定独立复核，待用户业务验收；P2～P5 仍后置。未获提交、推送或部署授权。

## 摘要

医生在 DSH 选择获准科室与时间、查看历史并制定／采纳 AI 修改；在 EMR 业务上下文中完整手工编辑同一参考稿。临床正文以 EMR 共享定义为准，DSH 轻量展示结构、差异、依据与问题，报告绑定同一参考修订。本组保留五个有独立验收价值的任务，统一要求见[共享数据与操作](clinical-pathway-workbench-model.zh.md)。

## 数据及前端归属

此表是已确认的职责决定，详细要求集中于 M-00／13；共享字段正本由 EMR 所有者提取，不在此项目另定义一套临床结构。

| 内容 | 所有者与消费方式 |
| --- | --- |
| 共享临床字段、枚举与必需结构校验 | EMR 拥有；双方消费同一可识别版本。排除 Angular 运行时、患者执行／审核状态；未入库引用、未知与完整覆盖由共享定义支持。 |
| 参考任务、临床正文、基线及参考修订 | DSH 私有任务保存唯一已提交参考稿；临床正文用 EMR 共享定义，元数据保存来源／覆盖／提案／锁定，不复制临床正文。 |
| 完整手工编辑及单路径查看 | emr-app 的同一业务组件，管理页或弹窗／抽屉承载；数据和动作由宿主提供，参考模式不持有医院业务写能力。 |
| AI 对话、修改、采纳、轻量预览与报告 | DSH；嵌入 EMR 时仍归 DSH 前端，EMR 提供宿主入口与受限上下文连接。AI 和手工编辑共用参考提交，不依赖 EMR 窗口在线才可运行 AI。 |
| 医院业务保存与未来写回 | 现有 EMR 业务宿主继续归医院流程；参考模式不触发这些动作。新导入／写回另立需求，不能由“采纳”或“保存参考稿”隐式授权。 |

<a id="split"></a>
## PRD 划分与依赖

保留五份，P1 完成共享定义和参考数据基础，P2 完成 EMR 原生消费与编辑，P3 服务科室分析，P4 提供受控 AI 修改，P5 形成可核对交接；没有按前后端机械拆成新平台。

| PRD | 独立可验收结果 | 前置依赖 | 后置范围 |
| --- | --- | --- | --- |
| [P1 EMR 共享定义与结构化参考稿](clinical-pathway-workbench-p1-draft.zh.md) | 双方消费同版临床定义；DSH 建立／恢复参考任务、轻量检查结构与差异，统一参考提交可用。 | EMR 现有模型／序列化器、既有读取器／Session；不依赖 P2 组件完成。 | 组件实际展示由 P2-A，完整编辑由 P2-B。 |
| [P2 EMR 单路径组件与完整参考编辑](clinical-pathway-workbench-p2-structures.zh.md) | A：无管理页／医院 ID 也能预览传入稿；B：全部手工字段和复杂变换提交回同一参考修订，医院维护不受参考模式影响。 | P1；授权的宿主连接与字典资料；不依赖 AI、分析或报告。 | 独立预览产品和医院写回后置。 |
| [P3 科室历史分析与候选](clinical-pathway-workbench-p3-analysis.zh.md) | 查看口径明确历史、点统计沿用人群、观察加入候选；参考编辑不改统计。 | P1 范围与证据身份；既有三工具。 | 新执行来源、历史试走后置。 |
| [P4 AI 制定与受控修改](clinical-pathway-workbench-p4-assistance.zh.md) | DSH 制定新稿或局部修改，逐项／批量采纳／暂缓／撤回；复杂提案遵循 EMR 共享语义。 | P1；用历史需 P3-A；完整复杂操作先完成对应 P2-B 语义验收，运行时不需打开编辑器。 | 无临床依据的参数仍待确认，不自主批准治疗。 |
| [P5 讨论报告与结构化交接](clinical-pathway-workbench-p5-handoff.zh.md) | 同修订报告、EMR 共享定义载荷、辅助记录、差异与缺口；实际组件消费已验证，而医院保存仍另议。 | P1；引用对应 P3／P4 结果；用 P2-A 验组件消费；既有复杂结构保真不依赖 P2-B，实际复杂变换再验相应操作语义。 | 医院导入／写 DTO、正式编号与版本后置。 |

依赖为 P1 → P2-A → P2-B；P1 → P3；P1＋所用 P3 → P4-A；P4-A＋对应 P2-B → P4-B；P1＋P2-A＋实际引用结果 → P5-A，保留的复杂内容不加 P2-B 门槛，实际复杂变换结果再验对应操作语义。P5 不向上游供必需数据，P2 可用确定性样本验收，不等 AI 才能开工；不新增循环。

<a id="stages"></a>
## 推荐分期与覆盖

推荐先验 P1，再并行推进 P2-A 与 P3-A；随后以 P4-A／P5-A 跑通新建和修订，EMR 单路径组件预览同一稿。P2-B 完整编辑与 P3-B 继续推进，再闭合 P4-B／P5-B。A／B 是交付深度，不是省略完整结构的许可。

| 里程碑 | 可观察结果 | 限制 |
| --- | --- | --- |
| M1：P1 | EMR 共享定义双方数据消费通过，DSH 新建／绑定版本、保存／恢复与轻量预览可检查。 | EMR 组件尚待 P2-A 实际验收，DSH 不提供完整手工表单。 |
| M2：P2-A＋P3-A＋P4-A＋P5-A | 获准科室／时间 → 历史 → 新参考或修订 → AI 局部修改／采纳／撤回 → DSH 轻预览与 EMR 弹窗／抽屉核对 → 报告／共享数据交接。两种任务各跑一次。 | 完整手工编辑与复杂 AI 变换后置；不能伪称已做临床验收或可写医院。 |
| M3：P2-B＋P3-B＋P4-B＋P5-B | EMR 完整手工编辑和 DSH 复杂 AI 操作在同一参考修订交错，冲突、锁定、重连、结构及报告一致性闭合。 | 医院保存、正式版本、审核发布与历史试走仍另议。 |

首轮可用标明的合成路径／字典补结构覆盖，真实读取不扩授权。简单 AI 演示只修改已支持对象，现有复杂内容原样保留；EMR 预览必须无损显示已承载复杂结构，不能裁剪后称完整。若首轮必须手工改整方／组包／跨日，P2-B 前移。

| 已确认能力 | 数据要求 | 行为归属与验收 |
| --- | --- | --- |
| 头／科室／住院日／费用、诊断／准入 | M-03～04 | P1 共享承载，P2-B 完整手工编辑，P4 提案。 |
| 阶段／日期／前驱、完整单条医嘱及诊疗／护理 | M-05～06 | P1 保留／轻预览，P2-B 编辑，P4 分期受控修改。 |
| 组包／合法选择、整方头与药味、阶段关联路径 | M-07～08 | P1 共享承载，P2-A 展示、P2-B 完整变换，P4-B AI。 |
| 共享字段／身份／未知与直接组件消费 | M-00～02、10 | P1 提取与消费核对；P2-A 证明实际组件接收参考稿；P5 交付同版数据。 |
| 点统计／历史候选、来源与依据 | M-01、10 | P3；不因参考稿编辑变化，不自动变临床标准。 |
| 选择对话、多项采纳／暂缓／撤回、讨论转清单 | M-09～11 | P4；使用 P1 统一参考提交，完整手工字段仍在 P2。 |
| 双端同修订、锁定／冲突／保存隔离 | M-09、11、13 | P1 保存权威，P2 宿主编辑联动，P4／P5 消费确切修订。 |
| 报告与结构化交接 | M-10～13 | P5；EMR 参考消费当前验收，医院写回后置。 |

<a id="acceptance"></a>
## 验收与待判断事项

每份 PRD 交付时提供运行版本、结构产物、成功／失败／边界证据，由用户或临床负责人说明预期、实际与通过理由。两仓源码、共享数据检查、真实 EMR 宿主联调与临床质量分别报告；文档 review 不替代用户验收。

| 待判断 | 建议与未确认时处理 |
| --- | --- |
| Q1 首轮演示深度 | 建议 M2 先跑 AI 与 EMR 只读预览，M3 闭合完整手工／复杂操作；若首轮即需手工复杂编辑则前移 P2-B。界面归属和数据以 EMR 为准已经确认，不再重复询问。 |
| Q2 临床依据与复核负责人 | 指定实际可读的指南／院内规范及负责人；EMR 空指南页不算来源。未落实时只验结构／交互，临床参数保留问题。 |
| Q3 首个真实任务 | 在既有权限内选新建与具体版本修订各一，说明不可接受结果；未选时用合成样本验结构，不扩真实范围。 |

评审发现、修正与检查见[评审记录](clinical-pathway-workbench-review.zh.md)。共享定义具体类型、包位置与宿主传输属于实施设计前置，不宣称已提取或联调；执行时分别核对两仓目标分支和环境，不以本轮只读源码分支替代部署映射。
