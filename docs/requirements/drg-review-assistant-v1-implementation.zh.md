# DRG／DIP 核查助手 V1 实施方案

[English](drg-review-assistant-v1-implementation.md) | 中文

状态：分阶段实施方案，2026-10-22。用户已确认出院前核查为主、DRG／DIP 分别预分组且不阻断出院。仅含来源的 DRG 归档和私有实例可选只读共享已实现；首个 EMR 读取器、私有核查 Session 及浏览器手动入口已通过本地验证，待用户验收；两种分组引擎仍属规划。

## 概要

依据[需求](drg-review-assistant-v1.zh.md)及[插件设计](drg-review-assistant-v1-plugins.zh.md)，在现有[私有工作区](sso-private-workspaces-v1.zh.md)上实现。运维发布版本化公共资料，私有 Session 拥有证据、确认和结果；复用 DSH Web、profile、作用域工具、skill 和持久记录。

独立完整国家 DRG 引擎仍是交付目标，DIP 分别建立资料及引擎验收。引擎不可用时可以推进证据核查联调，但不能计为分组验收。首轮 EMR 集成使用明确允许的一份开发库测试科室就诊、已授权公司 gpt-5.5 服务及可替换只读提供方。自动化 fixture 仅包含合成资料。MinIO、无限制患者访问、支付预测、医保申报及生产部署仍不在本次交付内。

## 资料存储与发布

### 存储与身份

已实现的首阶段归档原始 PDF、严格 manifest，以及只含来源／版本元数据的独立 SQLite 数据库。每个包均为 `profile: source-only` 和 `readiness.groupingReady: false`，参考默认版本不激活分组。下文完整结构化资料、字典、经复核抽取及确定性 TypeScript 引擎仍属规划。SQLite 是只读参考产物，与患者数据及通用存储域 KV 后端分离。

资料工具在运维配置的根目录下创建以下布局。发布路径属于 Docker daemon 所在宿主机的文件系统，可能不同于 gateway 文件系统或开发者电脑。

```text
<server-data>/drg/
  staging/
  published/
    catalog.json
    <pack-id>/
      manifest.json
      reference.sqlite
      sources/
        national.pdf
```

### 完整分组资料（规划）

manifest（元数据清单）标识资源 schema、包 ID、国家版本及适用范围、来源 URL 与 SHA-256 摘要、字典版本及摘要、整理数据修订、兼容引擎版本、必要文件、原文位置及核验报告。结构化资料覆盖 MDC／ADRG／DRG 关系、诊断／操作查询、优先及特殊条件、CC／MCC 与排除关系，以及不用于分组的编码。文件哈希识别字节变化；包是否获准发布由可信运维流程决定，不能仅靠哈希判断。

来源和抽取修订分别记录：PDF 未变而修正误读表格时生成新包修订，官方替换文件时同时改变来源摘要。引用文字保留物理／印刷页码及表／行位置。26／492／825 目录只是完整性检查之一，不能证明规则、编码映射或医学解释正确。

DIP 资料需独立来源清单、模式标识、字典／映射兼容性、病种匹配规则及带生效时间的可选分值表身份。现有 DRG source-only manifest 不能靠改文件名支持 DIP；持久资料格式扩展需明确读取器及兼容性评审，不重写已有不可变归档。

### 发布与读取

1. 运维在未挂载的 staging 存储中准备候选包，获取确切字典，核查依赖版面的抽取，记录专业复核及独立基准覆盖。合成测试包明确标识，与国家包激活隔离。
2. 发布器校验 schema、应有目录、引用、字典／引擎兼容性、必要规则路径、文件哈希和完整性报告。仅接受规范化的相对资源文件名，拒绝路径穿越及跳出集合的链接，发布树内不包含无关文件系统挂载。缺少必要资料时保持候选未激活，模型和运行中的用户工具都不能发布。
3. 关闭并定稿 SQLite 产物，不依赖活动 WAL／SHM 附属文件，再在同一文件系统内持久发布唯一命名的新目录。已有包 ID 对应不同字节时拒绝覆盖；仅在文件齐全后，才通过原子更新目录元数据将其设为可用修订／默认版本。
4. 只将 published 集合以 Docker 只读方式挂载进个人容器，同时以只读数据库连接读取。staging、发布凭据、私有 home 和 Docker socket 均不纳入该挂载。通过有大小限制的业务操作及标识查询，不接受模型提供的任意路径或 SQL。
5. 接受病例导入时解析默认版本，将确切包及文件身份写入已记录的功能状态。确认和发布结果前复核该修订的完整性、可用性和兼容性。并发修改默认版本本身不改变该病例的绑定，也不使其失效。
6. 回滚默认版本时选择已验证旧修订，不重写资料或 Session。撤回改变目录中的可用性，不改变包字节；恢复会话或下一次操作时，通过已记录功能输出显示撤回、使当前使用资格失效，并保留历史证据。运行中的计算须在发布前重新检查可用性。

该方案使用 [Docker 只读挂载](https://docs.docker.com/engine/storage/bind-mounts/)及 [SQLite 只读连接](https://www.sqlite.org/uri.html)。已发布包文件对发布方也保持不可变；替换修订应发布新修订，不在线编辑已挂载数据库。catalog 是可变发布元数据，独立于不可变包内容进行校验。

### 归属、备份与后续分发

只有指定服务器运维可写 staging、已发布资源及目录元数据。公司 SSO 登录或拥有个人 DSH 运行实例不授予发布权。用户可以查阅公开国家资料，但不能替所有人安装版本，也不能把私有副本冒充已发布来源。

在服务器之外备份原件、每个保留的已发布修订、目录元数据及核验报告；账号映射和各私有 home 沿用独立访问控制分别备份。启用分组前验证哈希及目录／文件恢复一致性。保留仍被历史病例引用的全部版本；V1 不做自动删包或备份迁移。

以后多台服务器需要同一集合时，可用 MinIO 分发不变的版本化产物。各服务器下载、校验后仍在本地只读使用。该扩展必须保留包 ID 和病例绑定；首批交付的查询不依赖 MinIO 可用性、bucket 策略或用户容器存储凭据。

<a id="runtime"></a>
## 运行实例与 Session 接入

实现[插件设计](drg-review-assistant-v1-plugins.zh.md#plugins)定义的四类能力及作用域工具集：就诊权限由可信读取器负责，已接受核查状态属于私有 Session，版本化国家资料属于只读集合；分组提供方消费各模式确认快照，不自行取原始患者记录。

[上下文字段](drg-review-assistant-v1-plugins.zh.md#context)、[工具调用](drg-review-assistant-v1-plugins.zh.md#tools)及[确认／恢复](drg-review-assistant-v1-plugins.zh.md#state)由设计定义。身份、修订、日志和取消要求须一起实现，preset 或登录成功均不提供患者授权，通用聊天能力保持既有行为。

EMR 出院事务独立于核查执行。如果等待模型、取数、人工回答或分组会改变原出院成功／失败结果，则集成验收不通过；核查失败单独展示并提供重试入口。

## 实施顺序

每个阶段是一个有明确范围的结果，包含接入点、前置条件、验收证据及恢复方式。阶段涵盖已实现资料共享、已授权首阶段证据核查及完整 V1 剩余工作，当前状态由进度表记录；列出阶段不授予生产部署权限。

| 阶段 | 工作与主要归属 | 依赖及可观察验收 | 失败、恢复与协调 |
| --- | --- | --- | --- |
| P0：资料与接口就绪 | 核实 DRG、DIP 来源／字典／规则、R1-R3 检查及独立病例；核实 EMR 启动、身份映射、来源修订和执行覆盖。 | 分别形成就绪清单并指定允许开发病例；实际访问前可先完成合成接口工作。 | 缺资料阻塞对应引擎，不阻塞独立核查；缺患者授权则停止真实取数。 |
| P1：制作与校验资料产物 | 新增功能拥有的 manifest／读取器／发布器模块及来源／抽取核验资产，将资源制作与运行时推断分开。 | 依赖 P0 资源规格，制作机制可用隔离的合成 fixture（测试前置数据）；有效候选完整发布，哈希、字典、覆盖或路径错误保持未激活。 | 保留失败 staging 供检查，不修改当前目录；已发布 ID 不可变，保留旧默认供恢复。 |
| P2：接入私有运行实例 | 修改 hosted-workspaces 配置、组合、创建／检查、部署接线及所属测试，接入一个已配置只读集合。 | 在 P1 布局确定后进行；两个个人实例读取同一包身份，真实文件／命令工具不能修改集合、看到 staging 或访问他人私有 home。 | 关闭可选资源配置可保留通用工作区行为；显式安排旧容器替换、保留 home 并处理运行中工作，不在 ensure() 中因挂载不符自动删除。 |
| P3a：完整 DRG 引擎 | 实现纯国家 DRG 库及注册提供方，包含可追溯规则和输入校验。 | 依赖 P0／P1 已核验 DRG 资料，独立于模型输出满足 DRG-08／09／10 和 AC-09／10／14。 | 不激活局部国家覆盖，保留此前已验证引擎／资料组合。 |
| P3b：DIP 提供方 | 按选定版本实现病种匹配及明确范围的分值计算，建立独立验证资产。 | 依赖 P0／P1 DIP 资料，满足 DIP-01／02 及 AC-20／21；缺分值资料时明确分值不可用。 | 不以 DRG 替代，不复用未经核实的 EMR 支付常量，失败限定在 DIP 模式。 |
| P4：私有核查与取证 | 实现受控读取器、Session 绑定、不可变证据、R1-R3 核查、模式修订及人工确认。 | 依赖 P0 接口定义及资料身份；验证明确缺资源、其他就诊、过时引用及中断回执。 | 发布前记录已接受状态；失败保留原状态，恢复时刷新访问授权。 |
| P5：工具、skill 与 EMR 入口 | 组合作用域工具、共用／模式 skill、可读报告及已认证事件桥接；对指定病例使用真实 SSO／公司模型开发链路。 | 依赖 P4；P3a／P3b 未就绪时核查明确计算不可用，计算验收另需对应提供方。 | 打开患者不自动完整核查；事件去重、保持当前修订，始终不阻断出院。 |
| P6：集成验证 | 执行聚焦行为测试、无密钥录制会话场景及真实 Docker／Web 流程。 | 覆盖 AC-01 至 AC-26、两模式、多用户／会话、提供方替换、修订、恢复／分叉、持久化失败、草稿不可用及非阻断失败。 | 分别报告核查、提供方、资料和模型证据，引擎不完整不能通过其完整验收。 |
| P7：演练交付与用户验收 | 资料发布／默认回滚、备份后替换实例、服务器外备份恢复，以及用户复核场景。 | 依赖 P6 及运维选定的服务器路径／备份目的地；恢复旧病例保留证据及确切资源身份，用户说明正常与失败场景的预期和实际。 | 回滚前确认镜像／功能 schema／资源组合兼容；验收前保留旧容器／镜像／配置及备份，公司部署或破坏性清理须另有授权。 |

依赖顺序：P0 身份／接口 → P1／P4；P1 → P2 及分别具备资料的 P3a／P3b；P4 → P5 证据核查联调，各就绪引擎再接入 P5 计算联调。P6 分别验证已交付部分，完整双模式验收须两种引擎均完成，P7 跟随已验收部分。复用现有 P1 原件归档及 P2 挂载，不重新建设；并行实施前先固定插件接口及写入归属。

<a id="validation"></a>
## 验证与验收

[需求验收表](drg-review-assistant-v1.zh.md#acceptance)拥有行为预期。每次实施验证记录仓库修订、工作区改动、选定资源／引擎／字典身份、环境、实际命令和结果。已发布 PDF、schema 校验通过或模型响应成功，都不能单独构成引擎或临床验收。

| 证据 | 必须覆盖的正常与失败场景 |
| --- | --- |
| 资源校验器及确定性引擎 | 必要目录与每个 DRG 经独立复核的可达病例，反例／边界、排除／优先、映射缺失、哈希损坏、引擎不兼容及资源缺失／撤回；发布／校验 CLI（命令行界面）路径使用与运行时准入相同的校验器。 |
| 私有流程与日志回放 | 确切原始消息导入、证据／截至时点／修订校验、不同用户／会话的同病例 ID、已接受与未记录确认、并发修订、默认发布与显式改绑、重启及更新后的历史解释。 |
| Docker 与 Web | 真实 SSO／网关／实例路由、双账号、多聊天、真实只读写入尝试、不能访问 staging 或他人数据、根 Agent 确认、取消、重启／重建、报告呈现和备份恢复。 |

开发中使用聚焦的资源／功能测试、所属运行实例测试及无密钥录制会话快照。代码改动完成前，按仓库要求执行构建产物／聚合检查、改动文档检查，以及模型辅助核查的真实模型／Web 流程。若 PR（Pull Request）改变可见 GUI 行为，附仓库要求的真实流程 GIF；静态截图或 mock 结果不能代替该证据。

运维验收包括 staging／发布中断、等待病例期间默认回滚、运行中结果发布前撤回、磁盘写满／资源缺失及历史病例恢复。独立用户验收包括正常、矛盾、缺执行资料、确认失效、跨用户拒绝和版本不支持。用户复核这些结果前，明确标为实现待用户验收；临床能力主张还需独立的专业规则／病例批准。

<a id="recovery"></a>
## 兼容与恢复

增加国家共享资料不将既有聊天迁入公共数据库，也不合并私有卷。保持当前 SSO 标识、私有 origin 路由、实例隔离及浏览器会话语义。挂载检查只允许确切配置的国家集合，不放宽其他挂载、宿主权限或同伴网络检查。

采用可选功能组合，使通用聊天仍能在当前无资料配置下运行。既有实例增加挂载／配置需要计划重建，不能只盲目重启或自动删除。保留 home 卷、备份网关身份映射、处理运行中进程／交互，并在替换更多容器前验证历史仍在。

资料回滚与应用回滚是不同操作。修改默认版本只影响新病例，保留旧包修订及可读日志证据。回滚镜像前验证其能读取已持久化功能记录 schema；否则暂停新 DRG 工作，恢复受支持镜像／配置，不替换已接受历史。不能重算时，通用历史工具文本仍可保持可读。

实施中若改变已发布 Session 判别字段或外部可见配置／API，先遵守仓库持久化类型确认、迁移、升级指南及消费者更新规则。本方案不授权破坏性数据转换，也不假设旧应用能够解释新功能元数据。
