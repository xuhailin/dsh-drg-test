# P5：讨论报告与结构化参考交接

[English](clinical-pathway-workbench-p5-handoff.md) | 中文

状态：2026-10-27 按 EMR 共享定义及组件消费要求修订，细节待审阅；依赖 P1，P5-A 用 P2-A 验证实际组件消费，保留的复杂载荷不依赖 P2-B 完整编辑器，按内容引用 P3／P4。总览见[分期规划](clinical-pathway-workbench-roadmap.zh.md)，字段与共享要求见[共享数据要求](clinical-pathway-workbench-model.zh.md)。

## 摘要

路径负责人可以从某个确切参考稿修订生成科室讨论报告和可检查的结构化交接包。报告说明范围、来源、改动、理由、待确认与覆盖，结构产物保留完整临床关系；收件人能核对报告与数据是否对应同一版。结构载荷必须已可由同版 EMR 单路径组件消费；这项当前验收与未来医院业务导入／保存分别判断。

<a id="scope"></a>
## 负责人任务与范围

起点是已保存参考修订，可来自人工编辑或 AI 提案采纳，允许仍有显式临床问题。结果是私有参考交付包及核对结果，支持会议讨论与后续人工处理；不要求用 AI 才能交付。

交付包含讨论报告、结构化定义、相对基线的差异、证据索引与缺口清单，全部绑定同一修订。报告优先展示科室要判断的事项，再展开阶段和项目，不强制堆放所有病例原文。不包含 EMR 导入包、业务草案、正式编码／版本、患者医嘱、审核材料自动提交、外发消息或发布站点。

<a id="requirements"></a>
## 行为需求与产物归属

P5 拥有固定修订的报告与交付记录，不反写参考稿。发现问题回到 P2 的 EMR 手工编辑或 P4 的 DSH 提案，P5 不修正临床内容，也不重算另一份历史口径。

| ID | 必须可观察的行为 | 模型依据 |
| --- | --- | --- |
| P5-01 | 生成前选确切已保存修订并显示任务、新建／修订目标、基线及人群范围；生成中有新修订则固定旧版并标非当前或重新生成，不能混合。 | M-01～02、11 |
| P5-02 | 报告包含用途和参考标识、适用人群／排除、数据范围及各来源时间、关键结构、改动及理由、重要依据、历史观察与临床建议的区别、待判断问题与覆盖。阶段／项目细节可定位到结构产物。 | M-03～11 |
| P5-03 | 输出 EMR 共享定义的同版临床载荷及配套辅助记录，保留全部临床字段、身份、容器／药味／前驱／分支、未知与来源；含共享版本、参考修订及格式标识。不另生成 DSH 专有临床 JSON 或在报告阶段才做字段映射。不是从报告正文再抽取一套结构。 | M-02、05～08、11 |
| P5-04 | 差异区分新增、修改、删除、阶段／容器关系变化，完整列出已采纳操作；暂缓／待确认提案不伪装已采纳，撤回保留记录但不出现在当前内容中。新建稿明确无医院基线。 | M-01、09～11 |
| P5-05 | 检查结果分开报告结构一致性、来源／字典覆盖、临床待确认与未来医院写入待核，不合成一个“可写入”绿灯。未知 code、参数未核、未读全来源和类型歧义均可定位。 | M-02、09～12 |
| P5-06 | 新生成结构产物须通过本地 ID 唯一、引用可解析、合法容器、日期区间与相同修订检查；不可解析的外部目标以引用和缺口保留。若本地结构失败，可交付明确失败的诊断报告，不生成“结构检查通过”的包。 | M-05～09、11 |
| P5-07 | 保存到用户私有 Session／指定的私有参考文件位置，展示文件、参考修订、生成时间和成功／失败状态；失败不破坏前一次有效交付。没有外发／医院提交回执。 | M-11 |
| P5-08 | 证据索引只含讨论必需的定位与摘录，默认不打包患者标识或整份病历；对不可访问依据说明限制。报告生成、导出与受限依据查看沿用现有私有权限和数据最小化要求，不因导出放宽。 | M-10～11 |

<a id="dependencies"></a>
## 数据前置与依赖

最小数据依赖是 P1 已保存参考稿、基线／范围与 EMR 共享版本。P5-A 在 P2-A 证明组件消费后验收，不能只验 JSON 可解析就声称已可带入 EMR。引用 P3 观察时保持其分母／时间／覆盖；引用 P4 时只用该修订的已采纳结果；未经复杂变换的既有载荷只需共享结构校验与 P2-A 实际消费，不等待完整手工编辑器；实际发生的复杂变换再核对相应操作已验语义，不要求 P2-B 全部界面完成。没有历史或没有 AI 的人工稿可以交付，但报告明确相应缺口／来源。

共享数据读取／结构校验、EMR 实际组件消费、临床质量与医院提交适配分别报告。前两项是本组当前交付，不得统称未来兼容而后置；后两项仍有独立依据与权限要求。既有来源异常允许作为诊断材料保留，不把异常清掉以通过检查；只有问题真实补足后才能更新对应检查结果。产品实现需要给出失败与重新生成路径，不要求先建设导入／回执／签名服务。

<a id="acceptance"></a>
## 验收场景

负责人从报告能找到结构中的同一对象，技术核对再检查完整字段与引用；两者都须通过，治疗质量仍另由临床复核。

| 场景 | 可观察通过条件 |
| --- | --- |
| 成功：新稿与修订稿交付 | 分别输出报告／结构／差异／缺口，标识一致；新稿无医院基线，修订稿引用确切定义版本，未声称业务保存。 |
| 成功：同版 EMR 直接预览 | 将实际交付的临床载荷及辅助记录送入 P2-A 的 EMR 参考宿主，无医院 ID 也展示同修订；不重新取医院旧版、不改字段名或补默认临床值，不发医院保存请求。 |
| 失败：共享版本不支持 | 组件不支持交付共享版本时明确拒绝，不降级删字段或显示成功；原报告与参考稿保持原修订，重生成须选择双方支持版本。 |
| 边界：完整编辑器未完成 | P2-B 未完成时，复杂原稿只改简单字段，保留的组包／整方／前驱／分支仍在 P5-A 全量交接并由 P2-A 核对；不能以复杂内容为由裁剪或拒绝交付。 |
| 成功：复杂结构核对 | bundle→group→single、三味整方、跨日阶段、前驱与关联路径全部保留；报告可定位同一本地 ID，未拍平或丢 code／单位。 |
| 边界：生成期间修改 | 生成 r2 时又保存 r3，所有交付文件仍一致绑定 r2 并显示非当前，或重新生成一致 r3，无混装。 |
| 边界：暂缓与撤回 | 已采纳、暂缓、撤回三条修改在报告中状态分明，当前结构只含当前有效改动，撤回历史可检查。 |
| 失败：本地结构破损 | 重复本地 ID、悬空前驱、非法嵌套或错修订的结构校验失败；给出位置和修复入口，不输出成功包。 |
| 边界：临床与字典未决 | 缺剂量、字典未匹配、来源未读全分别可定位；允许带清楚限制的参考交付，报告不说可写入或临床通过。 |
| 失败：保存或证据权限 | 导出失败有明确状态且前次包不损坏；受限证据不因报告生成而泄露患者内容，不自动发送文件给他人。 |

<a id="stages"></a>
## 分期与未来接入

P5-A 用已通过 P2-A 消费的同版共享载荷交付基础报告、辅助记录、差异和缺口，完成 M2；所有绑定／来源／未知规则均不能简化。P5-A 已覆盖既有复杂结构的保真交接；P5-B 对实际新增的复杂变换结果、关系差异和诊断报告补充验收，要求对应操作语义通过但不依赖整套手工界面，支撑 M3。PDF／Word 排版、模板中心、签名及批量导出后置，不阻塞可检查的参考包。

未来 EMR 写回单独确认实际 API 与多资源提交、权限和医院业务版本语义、字典／模板歧义、锁与冲突、部分失败与重试、审批发布和独立验收。P5 不开发这些功能，也不以它们作为参考包完成的前置；共享模型 M-12 的待核项随交接保留，不变成已经实现的适配能力。

<a id="dev-note"></a>
## 开发备注

本地保存不授权外发或写入医院；不同产物形式不能绕过本阶段只读参考范围；参考组件消费通过也不是医院保存授权。
