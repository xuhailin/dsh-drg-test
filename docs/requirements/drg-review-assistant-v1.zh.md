# 出院前核查与 DRG／DIP 预分组 V1

[English](drg-review-assistant-v1.md) | 中文

状态：产品定位已确认，首阶段实现已通过本地验证，待用户验收。以出院前核查为主，DRG、DIP 分别预分组，核查不阻断出院。公司 SSO、私有 Docker 工作区及仅含来源的 DRG 资料共享已实现；首个 EMR 读取器、私有核查 Session 及浏览器手动入口已通过本地验证，结构化人工确认和两种分组引擎仍属规划。

评审日期：2026-10-22。基线：DSH Web 0.2.1-rc.2 及当前 [SSO／个人工作区实现](sso-private-workspaces-v1.zh.md)。执行顺序和资源发布见[实施方案](drg-review-assistant-v1-implementation.zh.md)。

下一阶段的[结构化结果展示](clinical-result-viewer-v1.zh.md)草案约定聊天结果卡、可独立嵌入 EMR 的界面、稳定语义键及有限导航动作，不代表当前实现已扩展临床能力。

## 概要

帮助准备出院的医生核对拟填报诊断、操作和文书与住院证据是否一致。展示带原文依据的差异和缺项；人工确认对应编码快照后，依据明确的适用方案分别计算并解释 DRG 或 DIP 预分组。

首轮联调复用现有 DSH Web、公司 SSO 和公司模型网关，模型由用户选为 gpt-5.5。用户已允许该公司服务处理真实资料，并授权从开发库测试科室选取一份就诊；试用通过运维白名单将这一就诊绑定到试用账号，每个聊天处理一次住院。报告供医生、编码员和医保人员复核，不认证诊断成立、医保认可或支付金额。选择开发库不表示其中所有记录均可发送给模型。

## 使用者与范围

核查从医生准备出院、主动请求检查或要求复核已生成／修改文书时开始。打开患者只建立上下文，不启动模型分析。出院医嘱操作可以触发异步核查，但不证明已经离院，也不是充分的分组输入。具体 EMR 事件与启动认证须在启用前核验。

| 事项 | 决策或建议 |
| --- | --- |
| 已确认入口 | 出院前诊疗事实核查＋预分组；预期主要使用者是医生，编码员和医院医保人员参与复核。 |
| 已确认交付 | 复用 DSH Web、公司 SSO、已授权公司模型和私有实例；每个聊天接入一份明确允许的开发就诊，支持更正和重复核查。 |
| 已确认计算深度 | 保留独立完整国家 DRG 引擎目标，并新增独立 DIP 计算能力。DIP 确切版本、完整输入规则和验证集仍为依赖；两份模式提示词不等于两套引擎。 |
| 已确认 OpenDRG 用法 | 只参考需求和资料；不引入代码、引擎、数据集或网页产物，不以输出一致作为验收。 |
| 已确认共享存储 | 国家资料放在服务器持久存储中，按版本在用户和会话之间只读共享；MinIO 不是首批交付的依赖。 |
| 已确认私有工作区 | 复用现有每账号 Docker 运行实例和私有 home；共享资料不授予访问他人聊天、病例或文件的权限。 |
| 建议的有限核查范围 | 跨记录一致性、已记录事实的漏填候选，以及明确的诊断和操作填报规则。完整国家分组覆盖不表示覆盖全部疾病的临床诊断标准。 |
| 建议规则基线 | 国家正式 CHS-DRG 3.0，需核验资料、字典和优先规则；真实医院必须采用其实际地区版本。 |
| 已确认集成方向 | 接收 EMR 就诊上下文，先通过受控只读开发取数提供方获取资料，以后替换为公司 MCP；具体事件、标识映射、权限和确认传输仍须核验。 |

V1 不包括自主诊断、治疗或出院决策、全面用药／费用合规审核、整份病历自动编码、支付／盈亏估算、医保申报、病历回写、无限制患者访问、OCR、看板、批处理、模型训练或自主多智能体协调器。等待、超时、失败、缺证据、未确认或无法入组，均不得否决或延迟 EMR 出院事务。

一次成功核查应指出所用证据，区分已记录事实与待核实问题，记录用户的处置，并解释根据该次确认输入计算的预分组。不以提高支付金额作为诊断选择标准。

DRG 与 DIP 共用临床证据，但分别保留编码快照和计算结果。适用方案由可信机构配置确定，包括地区、生效时间、编码标准和规则修订；模型不能选择支付更高的模式。演示对比必须标明两套方案，任何结果都不能成为正式结算结论。

## 多用户与共享资料

平台拥有已发布的国家资料集合；会话拥有自己的病例和核查状态。共享资料是持久化资源，不是把其他聊天复制进模型上下文。新建聊天可以读取已安装版本，不必重新上传国家 PDF。

| 数据 | 归属与访问 |
| --- | --- |
| 国家原始文件、兼容字典、已复核分组／核查资源及其原文片段 | 由运维发布到服务器资料集合，所有已开通用户可读；用户运行实例和模型工具不能修改已发布资源。 |
| 病例包、执行证据、草案、人工回答、确认和报告 | 属于已认证账号的私有运行实例及确切 Session／就诊；其他会话不能通过提交标识继承其证据或确认。 |
| 地区或医院定制 | 不纳入首版国家共享资料集合；未来安装前另定版本、兼容性和机构访问权限。 |

原始 PDF 未变时，即使纠正抽取产生新的整理数据修订，其文件摘要也保持不变。分别标识国家版本、源文件摘要、字典版本、整理数据修订和兼容引擎版本。保留原件及已发布修订；来源更正和国家新版生成新资源，不替换旧字节。

接受病例导入时记录选定方案，固定已具备的确切兼容资料；缺分组资源则明确不可用，不妨碍独立证据核查。之后补装缺失资源属于显式的新模式修订，不能静默采用默认版本。确认及计算须有完整有效绑定；撤回使当前使用资格失效，但保留历史。

发送给模型的每个片段及资源身份均写入 Session，发布或回滚不能改写旧解释。缺少分组资源时停止依赖它的计算，独立的证据核查可以继续并明确覆盖限制；禁止以模型记忆或其他版本补算。历史日志仍可查阅，无法重算时明确说明。

现有网关选择私有运行实例，业务工具从 Host／Agent 获取当前 Session。SSO 不授予 EMR 就诊访问或资料发布权。通用 DSH 工具沿用既有策略；患者访问经过受控读取服务，凭据位于用户运行实例之外。专用 preset 是可选组合，不承担患者授权的强制校验。职责划分见[插件设计](drg-review-assistant-v1-plugins.zh.md#plugins)。

## 工作流程与示例

下表描述预期医院流程，文书完成、结账、编码、申报和医保审核可以交叉进行。手动核查与已验证异步 EMR 事件使用相同核查服务；首阶段浏览器手动入口已通过本地验证，实际 EMR 事件安装、结构化人工确认和计算仍需分别完成。

| 阶段 | 人员及工作 | 助手的作用 |
| --- | --- | --- |
| 住院治疗 | 医护人员记录诊断、操作、医嘱与执行。 | V1 不干预诊疗；这些记录随后作为核查证据。 |
| 准备出院 | 医生主动核查或执行已配置的出院医嘱操作。 | 绑定就诊并获取有截至时点的证据；出院小结尚未完成时仍核查已有诊断和操作。 |
| 文书生成或修改 | 草稿可读取或医生修改文书。 | 对照原始证据检查确切文书修订；生成不表示认可，文书不是唯一核查输入。 |
| 人工复核 | 医生解决临床疑问；编码员或演示中的复核用户确认编码及主次角色。 | 固定并展示待确认输入，记录问题的接受、更正、暂缓或排除。 |
| 预分组 | 复核者确认选定模式及其编码快照。 | 分别运行 DRG 或 DIP 提供方，解释路径、缺项或不支持方案，不混合两种计算结果。 |
| 申报前 | 编码员和医保办完成资料审核。 | 根据新快照重查；仅在版本和输入已知时对照外部分组。 |
| 医保审核结算 | 医院人员申报并处理医保反馈。 | V1 不执行医保交易或结算；未来反馈复核需另定需求。 |

合成示例：35 岁男性接受阑尾切除术，手术记录写有穿孔、局限性腹膜炎，出院诊断草稿仅写急性阑尾炎。本例用于说明记录核查，不代表已完成分组计算。

1. 用户提供诊断草稿、手术记录、相关病程、医嘱、执行事件及截至时间。
2. Agent 引用手术记录原文，询问出院诊断表述是否需要确认或补充，不自主增加穿孔或腹膜炎诊断。
3. 若病理或病程存在相反记录，保留为医生待核实问题；缺少证据保持未知，不作否定结论。
4. 人工核实后，用户提供或确认标准编码、诊断及操作主次角色，以及其他必要分组属性。
5. 系统展示确切快照，经明确确认后计算预分组，并给出规则依据。
6. 后续修订生成新版本，重新核查和确认；旧报告保留为历史，不能继续作为当前结论。

## 所需病历与执行数据

V1 接收已授权取数提供方的病例包，或已记录的合成用户消息引用。读取方保留来源原文和执行数据，模型生成的正文不能成为来源证据；两种入口使用同一病例包校验。全部来源属于一次明确允许的就诊，部署凭据及授权令牌不得进入病例包或模型上下文。

### 最小病例包与条件资料

最小病例包用于开展核查；计算分组还需要确认后的编码快照。缺少某项资料时，停止受影响的检查，不一定停止其他检查。报告列出无法覆盖的检查，不宣称整例通过。

| 数据 | 必需性与最少内容 | 用途 |
| --- | --- | --- |
| 就诊与截至时点 | 必需：case_ref、encounter_ref、修订、入院时间、带时区的核查截至时间、已提供的年龄和性别，以及拟出院与实际离院信息的区别。 | 隔离本次就诊，排除核查时点尚不可用的事实；天龄、出生体重、离院结局等条件字段按规则补充。 |
| 来源清单 | 必需：已提供文书的标识、类型、修订、事件和记录时间、作者角色、草稿／签署／修订状态、摘要，以及覆盖区间或明确缺口。 | 定位证据，区分缺资料与明确否定；提供方声明资料完整，不等于临床已核实。 |
| 拟出院信息 | 必需：带状态及拟主次角色的当前诊断清单、拟填报操作清单和已有文书修订；允许出院小结尚未生成、编码初始未知。 | 明确核查对象和各模式编码候选；缺文书记为缺口，不因此拒绝所有核查。 |
| 入院及病程记录 | 必需：入院记录／首次病程，以及截至时点内与诊断、诊疗有关的病程；提供文书目录，标出未提供或不可用项。 | 对照住院目的、确诊／疑似／排除状态、后续变化及当前填报。 |
| 医嘱索引 | 必需：截至时点内本次提供范围的完整医嘱索引，包含取消、停止、重开项，声明执行资料覆盖情况。 | 定位可能相关的诊疗；不完整导出中没有某条医嘱，不能证明未实施治疗。 |
| 执行事件 | 对每项声称已实施、需要核查的操作必需：实际状态、时点或区间、执行内容、关联医嘱和来源。适用时明确声明无记录或不可用。 | 判断已做、部分做、未做或仍未知。 |
| 手术／麻醉／介入 | 条件必需：手术及相关麻醉、操作记录，实际名称，适用的部位／入路，实际时间、完成状态和实施人员记录。 | 核实手术及操作事实；仅有拟行计划或医嘱不充分。 |
| 特殊诊疗记录 | 条件必需：诊断主张或规则涉及的呼吸支持、透析／CRRT、输血、放疗／抗肿瘤系统治疗等记录。 | 根据有依据的规则核实实际方式、次数、时长和可编码事实。 |
| 诊断相关报告 | 条件必需：被核查诊断引用的检验、影像、病理或会诊报告，包含报告时间、终版状态和相关单位。 | 找到支持或相反证据；单项异常不能独立确立诊断。 |
| 给药执行 | 当事实核查依赖用药时条件必需：药品医嘱和实际给药记录，包含药品标识、剂量／单位、途径、实际时间及执行状态。 | 区分开立、发药和给药；V1 不全面审核每种药的适应证、剂量、相互作用或医保支付限制。 |
| 费用及医保反馈 | 共同证据核查非必需；选定 DIP 调整需要金额时条件必需，保留来源与修订。支付参数、成本、报销比例、申报回执及医保决定仍不在 V1 范围内。 | 缺必要金额使依赖调整不可用；收费不能证明实际执行。 |

每份记录保留稳定的来源标识和修订、行号／记录号，以及原文或原始值。记录生成时间与临床事件发生时间分别保存。较晚形成、描述较早事件的报告，在较早核查时仍不可用，不能不生成新修订就加入原截至时点的核查。

### 执行事件字段与解释

病例包分别保留医嘱意图和执行证据。来源状态映射必须明确；未知枚举或单位属于输入问题，不能猜测。原始来源值可供查阅。

| 对象 | 适用时的必要字段 |
| --- | --- |
| 医嘱 | order_id、encounter_ref、修订、类别、内容／编码及可用的字典标识、开立时间、计划区间、停止／取消时间、来源状态、重开关联及 source_ref。 |
| 执行 | execution_id、关联 order_id 或明确的未关联说明、实际事件／区间时间、执行内容、状态、相关剂量／单位／途径或操作属性、更正／撤销标识及 source_ref。 |
| 时长／次数证据 | 方式、实际起止或截至时点仍在执行的状态、中断、单次治疗标识及计量单位；只有经过核验的规则才能规定合并与取整。 |
| 来源映射 | 明确状态、单位和标识的标准化方法，以及重复事件标识与修订替代规则。重复同步不增加给药次数或治疗时长。 |

执行前取消、部分执行后取消、执行完成后停止，是不同事实。取消不能抹掉此前有效执行。误记执行的撤销属于另一次来源更正。医嘱重开既不能重复计算，也不能删除相关执行历史。

缺少执行证据表示尚未核实，不等于未实施。计划结束时间不能替代实际时间。收费、发药、存在医嘱都不能单独证明治疗已完成。若分组阈值或编码解释缺少已核验规则，提出人工核实问题，不用自定的时长算法计算。

## 核查范围与职责

V1 限定三类检查。每项已安装检查声明所需来源、填报对象、版本化依据和支持条件；缺少资源时，该项检查不可用。目录定义记录核查，不定义覆盖所有疾病的临床诊断标准。

| 类别 | 包含的行为 | 不允许的结果 |
| --- | --- | --- |
| R1 跨记录一致性 | 对照诊断、操作描述、状态、否定、时间和执行；冲突时同时展示两处原文。 | 由模型偏好消解记录矛盾，或把既往／疑似／排除诊断当作当前确诊。 |
| R2 已记录事实的漏填候选 | 发现医师文书或操作执行记录中已明确的事实，未出现在拟填报清单时，提出复核。 | 根据孤立检验异常、用药、收费项目或更高支付机会增加诊断。 |
| R3 填报与编码疑点 | 核对有来源且明确支持的主诊断／主要操作填报条件、编码与名称一致性；候选保留到人工确认。 | 自主选择主要诊断、认证全部诊断临床成立，或使用无依据的填报经验规则。 |

主诊断填报核查建议以医保结算清单为目标。其[填写规范](https://www.nhsa.gov.cn/art/2021/8/30/art_140_8508.html)与[病案首页填写规范](https://www.nhc.gov.cn/yzygj/c100068/201606/2e3b6393fcff4f0095a45a507a975f2f.shtml)是不同来源；每条规则明确适用对象。读取首页作证据，不得静默切换填报标准。全面校验两套填报体系不在 V1 范围内。

| 负责人 | 职责 |
| --- | --- |
| Agent | 阅读有大小限制的来源片段，提出带精确引用的事实候选，发现疑点、补问，并解释已校验问题和分组结果。 |
| 确定性核查服务 | 校验病例归属、来源定位、可用时间、修订、单位／状态映射、快照完整性、已声明的可执行填报检查，以及是否满足确认条件。它能核对引文，不因此证明临床推断正确。 |
| 分组提供方 | 校验各模式已确认编码及属性，执行选定兼容规则，返回 DRG 路径或 DIP 病种匹配及明确的未得出结果；分值须有适用分值表。提供方不从文字推断诊断，不调用模型。 |
| 人工复核者 | 解决临床疑问，附理由接受／更正／排除候选，确认诊断和操作编码及主次角色。V1 记录演示用户确认，不认证其医师资质。 |

问题状态区分有记录支持、记录冲突、证据不足和结果待出，并带来源链接及明确的拟处理动作。文书有记录不等于诊断临床成立；任何发现都不是正式医保审核结论。必要证据缺失或分组相关冲突未解决时，不得确认。排除某项冲突必须记录理由和采用的事实解释，不能静默消失。

即使没有发现问题，报告也必须显示核查覆盖情况。未读来源与不支持的临床问题保持可见；“已核查资料未发现问题”不能变成“诊断和全部医嘱正确”。

<a id="confirmation"></a>
## 人工确认与结果生命周期

来源病例包、事实候选集、确认后的编码快照是不同记录。系统保留医生原草稿和模型建议，不互相覆盖。全部引用绑定本次就诊、来源修订和核查截至时点。

1. 校验病例包，展示资料目录和缺口。
2. Agent 阅读来源，提交事实候选及疑点；服务校验引用，返回固定的核查修订。
3. 用户处理阻止快照确认的疑点并提供或确认标准编码；这些疑点不阻断出院。选择“需要更正”时生成新候选，不构成确认。
4. 服务自行构造确认请求，展示病例、修订、截至时点、证据引用、问题处置、全部分组字段及规则／字典版本。
5. 对该次请求的明确回答生成绑定快照摘要的确认凭据。回答和凭据提交到 Session 日志后，分组服务才能使用。普通工具执行许可、模型传入的 confirmed 标志、待回答问题、跳过、超时或文字声称他人同意，都不构成确认。
6. 分组操作接收确认后的快照标识，验证仍有效，再计算携带同一输入摘要与规则身份的结果。

共同证据、截至时点或人工对共同临床事实的处置变化，使两种模式依赖的核查、确认及结果失效，即使来源字节未变也如此。仅模式专属编码、疑点或规则修订变化才单独使该模式失效。受影响快照重新核查并确认；仅排版变化不生成临床修订，历史结果仍可查阅。

串行接受同次就诊的修订，在接受确认和发布计算结果时比对预期修订。人工等待期间更新资料使该确认请求失效；计算期间更新资料，旧结果不得成为当前结果。不静默覆盖新修订，不复用中断且未提交的确认凭据。

分别显示核查进度与分组进度：核查可为待人工确认、需证据／处置或不可核查；分组可为待确认、需输入、不支持，或已完成并得到具体病组／歧义／无法入组结果。完成核查操作或输入合法，都不保证一定得到病组。不用单一绿色“通过”合并临床核查和医保认可。

<a id="requirements"></a>
## 行为需求

需求编号保留原 DRG 前缀以便追踪；除明确限定 DRG 的条目外，共同要求同样适用于 DIP。核查覆盖、各引擎完整性和 EMR 集成分别验收。

| 编号 | 需求 |
| --- | --- |
| DRG-01 | 导入已授权提供方病例包或已记录的合成原始消息，限定一次就诊；保留来源、修订、截至时点、覆盖和未知值，拒绝混合就诊及无效单位／状态映射。 |
| DRG-02 | 区分草稿、疑似、排除、既往、有记录、模型候选和人工确认事实；不根据治疗或缺项推断疾病。 |
| DRG-03 | 每项实质发现引用同一病例包修订中可读取的原文或记录；冲突引用双方。引文不匹配或未来资料不能作为依据。 |
| DRG-04 | 分别解释医嘱意图与实际执行，保留部分执行、取消、撤销及去重后的事件。 |
| DRG-05 | 只执行已声明且前提资料齐全的 R1-R3 检查，显示不可核查项及分组相关的未决问题。 |
| DRG-06 | 用户经可信交互确认固定的编码快照后才能分组；模型不能通过声称批准生成确认凭据。 |
| DRG-07 | 每次结果绑定输入、证据、确认、规则、字典及核查修订。实质修订使当前确认和分组失效。 |
| DRG-08 | 覆盖选定完整规则包的全部国家 MDC／ADRG／DRG，以及所需优先、排除、特殊及无法入组路径。不能把漏实现国家病组标为不支持。 |
| DRG-09 | 仅使用身份明确且兼容的规则、字典；必要资源缺失时规则包不得激活。未安装地方定制返回不支持，不回退到国家版。 |
| DRG-10 | 返回带采用字段与依据的确定性分组；模型不得改写病组编码，不得丢弃诊断或操作强行入组。 |
| DRG-11 | 外部分组与本地预分组分别标记。输入或版本不一致时，不得断言医保或本地结果错误。 |
| DRG-12 | 通过 Session 保留有大小限制的输入、精确证据、候选、人工回答、确认及结果；重载保留旧身份和当前／失效区别。 |
| DRG-13 | 每个会话绑定一个 case_ref 与 encounter_ref，拒绝在原会话切换就诊，不跨会话复用事实、证据或确认。 |
| DRG-14 | 运行失败使用 DSH 原生取消／错误，不伪造成功元数据；中断且未记录的确认必须重新取得人工操作。 |
| DRG-15 | 来源文字是不可信数据，不是指令或授权。开发模型联调须明确授权就诊及接收服务；自动化测试仍使用合成资料。数据库名称本身不授予取数权限。 |
| DRG-16 | 不从成功分组直接给出支付、盈亏、临床认可或医保认可结论。 |
| DRG-17 | 已安装国家资料可跨用户和新会话读取，不需反复上传；发布到服务器持久存储，用户运行实例仅获只读访问。 |
| DRG-18 | 病例引用、证据、草案、确认和结果限定在当前私有运行实例及 Session／就诊；拒绝其他账号或会话的标识。 |
| DRG-19 | 记录来源摘要、整理数据修订、字典版本和引擎兼容性；纠正抽取与修改官方来源分别产生不可变的新修订。 |
| DRG-20 | 接受导入时固定可用资料修订，缺资料则明确标记；重启／默认版本变化保留绑定，显式补绑或改绑后重新核查和确认。 |
| DRG-21 | 不完整／损坏的包不得激活，撤回包不能用于当前分组；保留历史报告，不静默替换缺失版本。 |
| DRG-22 | 资料发布位于模型工具及用户运行实例之外；版本发布／回滚保留私有 home、已接受的 Session 历史和旧资源。 |
| DRG-23 | 从已验证适用方案选择模式，分别保存 DRG／DIP 编码清单和结果，记录模式、地区、生效版本、字典及引擎身份。 |
| DIP-01 | 将确认快照按选定完整 DIP 规则匹配，覆盖适用的核心／综合病种及调整路径，保留命中组合与规则引用。缺少分值资源不能生成虚构分值或金额。 |
| DIP-02 | 按 DIP 自身版本清单及独立正例、反例、边界病例验收完整性，DRG 测试或既有 EMR 导出公式不能证明 DIP 正确。 |
| EMR-01 | 打开患者只建立就诊上下文；验证并去重已配置核查事件后，才启动异步分析。 |
| EMR-02 | 每次临床读取独立校验权限，核实来源标识映射并执行指定测试病例白名单；替换数据库／MCP 提供方保持这些限制。 |
| EMR-03 | 来源刷新、文书修订、切换患者、重复事件、超时、取消及提供方失败，不能把其他就诊或旧修订结果发布为当前结果。 |
| EMR-04 | EMR 出院操作独立于核查、确认及计算完成。失败仅展示核查状态和重试入口，不能否决出院或伪造检查成功。 |

<a id="technical"></a>
## 插件设计

[插件设计](drg-review-assistant-v1-plugins.zh.md)负责插件职责、触发顺序、上下文字段、工具、各模式输入、确认、持久化、失败处理及提供方替换。复用 DSH profile、作用域工具、skill（技能）和 Session 历史，业务规则不进入 agent loop（智能体循环）或 SSO 网关。文中描述完整 V1 目标，所链接的包 README 定义首阶段已实现子集及当前 API。

共同证据、编码快照、规则资料和计算结果分别保存。计算读取确认快照，不接受模型重写编码；提示词不实现权限校验或分组算法。报告区分临床疑点、计算状态、未覆盖项和人工处置。

<a id="integration"></a>
## EMR 集成与可替换取数

首个适配器接收 EMR 就诊声明，先依据服务端就诊白名单核对 SSO 身份，再执行有界只读开发库查询。试用采用已授权公司模型网关，明确来源映射及覆盖；浏览器声明本身不授予访问权。原始数据库凭据位于私有工作区之外；任意 SQL 和自由患者选择器不是模型工具。

后续 MCP 提供方须保持相同的就诊范围、证据响应、修订、权限和取消语义。现有 [MCP 客户端](../../packages/mcp/mcp-client/README.zh.md)提供传输，不代表已有临床服务端或自动医生令牌委派。下游 agent 摘要不能替代核查所需原始记录。

独立 DSH 使用根 agent 的人工交互通道；委派执行向可信调用方返回待确认请求，只接受绑定确切快照且经过认证的人工回答。演示确认不是临床资质。切换患者应打开或恢复另一个已授权 Session，不改变原 Session 的就诊。

<a id="acceptance"></a>
## 验收

使用有独立预期疑点、人工处置、编码及分组结果的合成病例包。临床和填报预期须经专业复核，才能据此提出临床能力主张。引用校验是确定性的；模型解释看似合理，不是验收标准。

| 编号 | 场景 | 可观察结果 |
| --- | --- | --- |
| AC-01 | 手术记录有事实未体现于诊断草稿；配对病例中存在明确相反记录。 | 引用相关原文，要求人工核实，不自动增加诊断或确认编码。 |
| AC-02 | 只有药品医嘱或单项异常检验提示某疾病。 | 不生成已确认诊断、不送入分组，显示证据不足或不支持的临床问题。 |
| AC-03 | 一条医嘱执行前取消，另一条部分执行后停止。 | 前者不当作已实施，后者保留实际执行；不套用自定时长阈值。 |
| AC-04 | 出现重复同步、医嘱重开及执行记录撤销。 | 不重复计数，区分执行历史与来源更正，保留对应引用。 |
| AC-05 | 必要执行资料缺失或报告待出，随后补充终版报告。 | 显示受影响检查不可用／待出；旧截至时点不采用较晚报告，新修订才能使用。 |
| AC-06 | 模型重写来源、编造引文、引用其他就诊，或病历含批准快照的指令。 | 只导入已记录原始消息或已授权提供方响应；拒绝无效引用，不将来源文字当作授权或确认。 |
| AC-07 | 确认后、等待确认时或分组运行中，证据、编码或规则修订变化。 | 拒绝过期确认，将旧结果标为历史；新修订重新核查和确认前，旧计算不得发布为当前结果。 |
| AC-08 | 问题被跳过、超时、取消、中断，或由运行时归属其他 Agent 的子 Agent 发起。 | 不伪造确认；保持待确认或原生失败，未来委派请求交父 Agent 处理。 |
| AC-09 | 确认输入完整；配对病例缺条件属性或兼容规则包。 | 前者给出有依据的确定性结果；后者明确缺项／不支持／资源失败，不替换版本。 |
| AC-10 | 遍历全部国家病组及必要判定／排除路径。 | 每个 DRG 至少一个独立审阅的可达正例，并有反例／边界样本；国家清单无遗漏，局部覆盖不能通过完整 V1 验收。 |
| AC-11 | 外部分组采用不同版本或输入，当前病例又被修订。 | 说明不可直接比较，保留双方身份及新旧快照，不断言医保错误。 |
| AC-12 | 规则包更新后重载会话，两个会话核查不同就诊，再向原会话提交新就诊。 | 恢复原证据及失效／当前状态，保持隔离，拒绝切换就诊。 |
| AC-13 | 分组期间取消或模型／提供者失败。 | 原生错误／取消可见，不伪造新的成功分组或成功元数据。 |
| AC-14 | 在 DSH 外调用同一确认业务操作，并检查模型最终解释。 | 确定性分组一致；每项实质解释有有效病例／规则引用，不增加支付或临床认可结论。 |
| AC-15 | 两个 SSO 账号及多个新会话查询同一已安装国家版本。 | 无需重新上传即可读取同一身份的资源；病例、文件、证据和确认仍私有，伪造跨账号／会话标识也不能访问。 |
| AC-16 | 用户通过文件／命令工具尝试修改或替换共享集合，再重建其容器并重启网关。 | 写入失败，其他用户的资料哈希不变，持久集合和私有病例的资源绑定保留。 |
| AC-17 | 病例等待确认或计算期间发布／回滚默认版本，再显式改绑该病例。 | 原病例保留固定修订，新导入采用选定默认；改绑使旧确认／结果失效，重新核查和确认前不能作为当前结果。 |
| AC-18 | 发布中断，发现校验和／字典／引擎不匹配，或修订缺失／被撤回。 | 不完整包不得激活或提供当前分组；明确显示资源失败／状态，保留历史内容，不回退其他版本。 |
| AC-19 | 从备份恢复资料集合及私有 home，再重载历史病例。 | 恢复原身份和已记录证据，重算前核对精确资源摘要；缺少修订时明确说明，不采用当前默认。 |
| AC-20 | 对同一证据运行两模式，先更正单模式编码，再在来源字节未变时更正共同事实解释。 | 模式专属更正只使对应模式失效，共同事实处置使两者失效；各模式结果和确认保持独立。 |
| AC-21 | DIP 资料完整，或缺病种规则／分值表／兼容引擎。 | 独立 DIP 病例验证匹配及已支持分值；缺项明确显示，不借 DRG 替代，不虚构支付。 |
| AC-22 | 打开患者，重复触发核查，切换患者，并在分析中修改文书。 | 仅打开不请求模型；重复事件不重复核查；迟到结果保留原就诊／修订，不成为新对象的当前结果。 |
| AC-23 | 出院时模型、数据库、MCP 或引擎失败，或人工确认一直未回答。 | 原 EMR 出院操作照常完成；核查展示失败、缺覆盖或等待状态，不伪造通过。 |
| AC-24 | 有效 SSO 账号提交他人就诊、冲突标识或白名单外开发病例。 | 患者正文进入模型前拒绝读取；数据库和 MCP 提供方执行相同限制。 |
| AC-25 | 尚无出院小结，或生成通知先于可读正文，返回的是旧草稿。 | 继续核查已有证据并明确缺口，不以旧草稿替代；新正文就绪后按新修订重核，重复事件去重，出院保持独立。 |
| AC-26 | 人工更正编码／主次角色，或确认落盘失败，随后重试／重启。 | 更正产生新未确认快照，重新接受后才允许计算；未确认落盘按操作 ID 核实，不能当作确认成功或自动回滚。 |

固定核查验收集要求每项实质发现引用有效，不自动确认诊断／编码，并正确处理每种确认／计算前置条件。分别记录漏报和误报，不用合成测试宣称临床敏感度、特异度或与医院一致；核查目录与完整分组清单分别报告覆盖情况。

实施验证包括聚焦业务／适配测试、无密钥录制会话快照，以及包含提交病例包、补问、人工确认、分组、修订和失败的真实 DSH Web 流程。文档检查不是功能验收。实施后提供测试版本和证据，由用户验收正常、矛盾、缺执行资料、确认失效及版本不支持场景。
