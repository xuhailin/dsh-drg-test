# 临床路径工作台：共享数据与操作要求

状态：2026-10-27 按已确认的 EMR 数据权威与完整编辑归属修订；本文件约束 P1～P5 的共享要求，临床字段／枚举以 EMR 提取的共享定义为权威，不另立 DSH 临床 schema。P1 在 EMR 提取版本化纯数据定义，DSH 消费带摘要校验的镜像；EMR 组件实际接入仍属于 P2。

## 摘要

DSH 的轻量预览、AI 修改与采纳、EMR 的完整手工编辑及报告必须指向同一参考稿修订。这里集中说明共享要求与完整性检查；下列临床字段组是覆盖要求，不能据此新建与 EMR 不同的字段名、枚举或临床存储结构。双方引用或从同一 EMR 正本生成版本化定义，包划分与分发方式留实施设计。

## EMR 数据权威与前端职责

M-00 是用户已确认的分工：EMR 拥有临床路径共享定义及完整业务组件；DSH 拥有分析、AI 提案、参考任务与轻量预览。DSH 不建设临床字段表单或第二套完整编辑器，EMR 单路径组件可由管理页、弹窗或抽屉承载，不要求独立预览应用。

共享内容是可序列化的路径定义，抽取自 EMR 临床字段与枚举，覆盖 M-03～08。已有接口 DTO、Angular 类实例和界面状态不是同一份可交换数据；共享定义排除患者执行、审核、选中状态、临时库存及 HTTP 服务依赖。必要结构校验随共享版本说明，双方不得手写各自的字段副本或仅在末期约定映射。

共享定义必须表达未入库引用、未知值、未读完整部分以及 EMR 现有转换可能丢失的临床信息。若原模型不能表达，先由 EMR 共享定义补足并由其组件消费，DSH 不单独扩一套临床字段。构造运行时实例可做身份解析与界面投影，不能重解释临床语义、丢失原值或用缺省掩盖未知。

临床正文、原始只读来源与 AI 辅助记录分别保存；辅助记录承载任务／参考修订、本地身份关联、来源、覆盖、未决、提案和锁定，不复制另一份临床正文。两端展示、交换与报告均标明共享定义版本；不支持的版本明确拒绝消费／提交并保留旧稿，不能静默降级或删字段。

<a id="identity"></a>
## 任务、身份与基本定义

参考任务是医生工作的上下文；参考稿是可编辑临床定义；历史观察是独立证据。三者不得互相覆盖。

### M-01 任务与范围

每个任务有本地稳定身份、目标（新建／修订）、目标科室与诊断、确切分析范围及当前参考稿。分析范围保留来源系统、医院、科室集合、科室口径、诊断编码系统／类型／条件、时间字段、带时区的半开区间 `[from,to)`、授权范围引用及读取时间。最近一年转换为确切起止后固定；切换范围创建新的分析上下文，不重标旧统计。参考稿适用科室不授予该科室的取数权限。

新建参考稿没有医院定义身份；修订稿必须绑定确切来源定义、系列、业务版本与读取时的状态，不只记路径名称。基线保持不可变；新读到源定义变化时展示差异与过时提示，医生选择重建基线或另起任务，不能静默替换当前基线或用户编辑。跨任务证据只能显式引用并显示原范围。

### M-02 身份、字典与修订

本地任务、参考稿、阶段、项目、容器、整方药味与分支关联各有稳定且唯一的本地 ID。显示排序、名称、日期和数组位置不是身份。本地身份与新对象引用由 EMR 共享定义及其辅助身份约定承载，往返两端保持稳定；不向现有数字业务 ID 字段塞入 UUID、负数或虚构正式编号以适配旧组件。来源系统／医院、来源定义／节点／项目身份、字典内部 ID、业务 code、名称分别保存；缺少任一项不从另一项猜补。复制生成新的本地 ID，原来源身份只保留为“复制来源”，不变成新对象的医院身份。

字典项记录来源、读取时间／可用版本及匹配状态：已匹配、未匹配、多个候选、来源不可用；无完整字典时不能把现有路径项目表当完整药品目录。名称输入可以成为参考占位，不能伪造 code 或内部 ID。相同名称、不同规格或单位的候选须区分。

参考稿保留格式标识与格式版本、本地参考稿 ID、递增参考修订号、不可变基线引用与当前内容。参考修订 `r1/r2` 不是医院 `versionNo`；模型不能分配正式 definition ID、pathwayCode 或业务版本。格式版本只说明本地产物解释方式，不承诺 EMR 可导入。

### M-03 路径头与科室

保存路径名称、说明、所属科室、使用科室、住院日下／上限、费用下／上限及币种／来源口径。来源未提供币种或值时标未知；费用为参考范围，不是预测或承诺。所属科室和使用科室分开，保留 code／名称与来源；下限不能大于上限，未知不默认成 0。

<a id="clinical"></a>
## 临床结构

这些是必须可表示、检查和保留的业务内容。P1 即须无损承载已有复杂内容，P2 再提供完整复杂变换；未支持编辑不能成为静默删字段的理由。

### M-04 诊断与准入

诊断集合保留诊断 code／名称、编码系统、来源身份、顺序及来源已经声明的组关系；没有组合逻辑时不推定 AND／OR。准入项保留纳入／排除类别、依据分类 code／名称、条件正文、必评项及顺序。正文与 `[basisKindName]` 显示前缀分开，展示拼接不回写进正文；无法解析的来源条目保留原值与待核问题。

### M-05 阶段与日期

阶段保留名称、临床属性、日期基准（住院日／手术日／出院日）、日期下／上界、前驱引用、显示顺序及来源节点身份；区间可跨多天。日期基准和区间共同解释“第几天”，不能把手术日偏移当住院日。来源未知枚举／区间保持待核，不自动重排、合并重叠区间或把所有阶段拆成每日卡片。

新增／复制／删除／拆分／调整阶段都保留项目归属、容器、药味、前驱、分支、锁定和证据引用。复制时内部引用指向新副本；外部引用列明保留或重定向，不制造悬空引用。拒绝新建前驱环、自引用或逆序区间；既有异常可以保留为问题，不能借异常自动修临床内容。删除有引用对象前，必须预览受影响项并选择明确处理方案，取消不改变参考稿。

“第 3 天 X 改 Y”命中住院日第 3—4 天共用阶段时，必须先展示该阶段、命中项目／组内关系及两种范围：整阶段修改（第 3、4 天均变）或仅第 3 天（需拆阶段）。日期基准或目标不明则先定位问题。仅某日方案必须展示拆分后的区间、项目复制、前驱和分支引用处理，再获得该次确认；没有确认不应用任一范围。

### M-06 单条医嘱、诊疗与护理

单条医嘱区分药品、检验、检查和手术申请，保留字典身份与业务 code／名称、分类／子类、规格、剂量值、剂量单位 code／名称、基本／最小／包装单位与换算资料、用法 code／名称、长临类型、频次 code／名称、天数、嘱托、必做、剂量可变、自备、可重复、执行科室 code／名称及申请／模板关联。类别不适用字段显式为不适用；来源缺值保持未知而非删除该语义。剂量 0 是原值，不当作未填或临床有效性的证明。

诊疗／文书工作与护理工作各保留具体字典／模板身份、业务 code／名称、必做规则、顺序和来源；不能只保存自由文本标题。字典身份存在历史歧义时保存原始字段与候选解释，标记未核定，不以名称匹配消除歧义。

替换药品必须重新检查目标药品规格、剂量、单位、用法、频次及长临适用性。旧值可以显示对照，不能自动成为新药已确认值；没有可核依据的参数置待确认，并保留原药的撤回依据。检验／检查／手术替换同样复核相关申请与模板，不能仅替换显示名称。

### M-07 成组、组包与选择

本文用 `single`、`group`、`bundle` 描述单条、成组和组包；交换时使用 EMR 共享定义的实际字段与枚举，不新增 DSH 字符串标签。group 只包含 single，bundle 包含 single 或 group。不接受 group 套 group、group 套 bundle 或 bundle 套 bundle，不把容器拍平为互不相关的项目。各容器有本地身份、顺序、名称／来源、必做／可重复及明确选择规则；未知规则保留未知，不能把“可重复”“单选／多选”“必做”混成一个开关。

维护成组时检查所核 EMR 规则：药品单条、非整方、适用的用法及相同执行科室；不能因类型合法就认定临床可成组。组内共用字段、子项特有字段和选择规则分别保留。已核组内联动包括用法、频次、执行科室、天数、必做及可重复，频次还关联长临；修改共享字段必须预览全部受影响成员，剂量等单项字段仅影响其目标。EMR 现有单选／多选模式切换会清除子项必做，单选组包内调整必做也影响其他候选；工作台须逐项展示拟清除、保留或转移的值，经确认才应用，不能静默照搬清除。解绑／移入／移出同样显示规则及字段变化。未核规则或目录不可用时可保存有缺口参考稿，但不能标成兼容校验通过。

### M-08 中医整方与关联路径

整方是处方头加有序药味，不是单个药名。处方头保留名称、长临、执行科室、付数／代煎付数、用法及辅助用法、频次／服用频率、煎法、治则、备注、特殊用法、代煎／处方／门诊标记、草药类型、煎药量与次数。每味保留本地身份、来源身份、药品内部 ID／code／名称、分类、规格、数量／剂量、剂量／基本／发药／最小／包装单位及相应编码、换算量、用法／炮制资料、顺序和备注。

整方按当前已核 EMR 能力只采用临时医嘱；其他长临要求标记为兼容待核，不静默转换。关联路径是“阶段 → 另一条具体来源路径”的引用，保留目标定义／版本／状态、关联临床属性、来源及读取覆盖；不是嵌套任务树。目标不可读或环形关联时保留引用与限制，阻止无限展开，不虚构目标内容。

<a id="operations"></a>
## 操作、证据与产物

同一临床语义与参考提交规则约束 EMR 手工编辑和 DSH AI 提案；DSH 点击负责选择、采纳、暂缓、锁定和撤回，临床字段表单在 EMR。应用后的已保存结果只有一份。

### M-09 修改、锁定与撤回

每个变更保留目标本地 ID／字段、基于的参考修订、改前／改后、影响范围、理由、证据、依赖变更、未决问题与发起方式。EMR 参考表单提交产生可撤回修订；删除、替换、跨日／容器／引用变换先预览后确认。AI 输出一律先成待采纳提案，不直接覆盖当前稿。关联变更作为不可拆分事务应用，彼此独立的变更可逐项采纳或合成一个批次。

提案状态区分待处理、待确认、暂缓、已采纳、已撤回、已过时与失败；不接受仍缺范围确认或依赖未完成的变更。采纳时重核当前修订、对象存在、权限及锁定；同一提交重试不重复应用。原子保存失败不产生半个新修订，已确认旧稿继续可用。

同一清单 A、B 都基于 r1，采纳 A 成为 r2 后，B 不因修订号变化一律失效。系统在当前修订重核 B 的目标原值、依赖、范围解释、引用与锁定；全部未受影响时，更新 B 的预览基准并记录核对结果，医生可继续采纳，无需重新生成整份清单。任一项受影响则将 B 标过时并重新预览确认，不覆盖独立人工编辑；其他暂缓项保持暂缓。

锁定可针对对象或字段，结构操作涉及锁定子项时也算触碰锁定；模型不能解锁，用户显式解锁后才可再预览。撤回创建可检查的补偿修订并保留原记录；若后续变更依赖被撤回内容，必须列出受影响项、选择连同撤回或重新提出修改，不能覆盖其他独立编辑。

### M-10 证据、覆盖与临床未决

证据引用保存来源类别（历史观察／计算／指南或院内规范／人工意见／模型推断）、来源身份、原始范围、读取或资料时间、版本／片段及覆盖。完整、部分、未读、不可用、不适用与未知分开；未匹配字典与未读全来源分开。每个问题可定位到具体对象／字段并说明缺什么、如何补足以及阻断哪些操作，按阻断影响集中呈现，不能散落大量无定位追问。

历史观察与候选区不属于参考稿定义，修改参考稿不能改变原统计、分母或来源时间；加入参考稿需要另一个待采纳提案并保留观察身份。实际执行、疗效和费用收益不能从医嘱存在、系统完成标记或观察频率推得。用户资料也保留来源类别，不能被模型升级为指南。

### M-11 保存、检查与交付

私有 Session 保存足以恢复确切参考修订、基线、变更、锁定及证据引用的记录；模型看到的结构与证据必须可从已记录内容还原，不能依赖未记录的浏览器状态。刷新及模型失败不丢已保存人工修改；授权失效后阻断新的来源读取及需重新访问来源的依据查看；已保存材料沿用既有私有 Session／文件策略。本组不承诺追溯隐藏旧日志内容或收回已导出文件；若需此能力，须另行定义权限与留存需求。

结构检查、DSH 轻量预览、EMR 单路径组件和报告读取相同参考稿修订及 EMR 共享定义版本；只读 JSON 检查不建立第二个可编辑正本。产物至少绑定本地任务／参考稿／格式版本／参考修订、来源基线、分析范围、各来源时间、差异、证据引用及缺口。报告生成期间有新修订时，固定输出所绑定的旧修订并标记非当前，或重新生成；不能混装多个修订。

### M-13 跨宿主参考编辑与提交

DSH 私有参考任务是已保存参考稿的唯一事实来源，EMR 只持有绑定任务、本地参考稿、共享版本与基准修订的临时工作副本。宿主提供加载与提交能力；预览初始化／切页签／关闭不得隐式查医院定义、修改传入快照、创建业务记录或触发保存。当前业务维护仍由自己的宿主连接医院流程，不与参考模式共享业务写能力。

AI 选择只指向已提交参考修订中的对象。EMR 未提交新增对象、已改目标或相关依赖不能冒充已保存选择，须先提交参考稿或明确放弃相关修改，再发起该目标 AI 操作；可取消并继续编辑。未受影响的已保存对象仍可选择，传入时说明当前基准并重核依赖，不把旧值当成本地最新值。

宿主可拦截的关闭或切任务前，若有未提交编辑，须显示状态并允许继续编辑、明确放弃或提交参考稿后退出；提交只走 P1，失败或结果未知时停留处理，不调用医院保存。取消退出保留工作副本，明确放弃不改已保存稿；强制登出、页面重载或进程丢失不承诺未提交副本恢复，旧绑定失效后也不能把副本显示给新账号或新任务。

手工提交携带基准及候选差异、提交身份和目标上下文，由 P1 核验并原子提交；不能以整份旧工作副本覆盖当前参考稿。成功返回确切新修订，再更新两端；失败保留旧修订和本地未提交编辑，未知结果先用同提交身份核对状态，不能另起医院保存。与 AI 修改独立的内容按 M-09 重核后可提交，受影响内容重新预览确认。

连接校验实际调用方、允许来源及窗口／连接身份、登录关系与参考任务权限；EMR 登录不是 DSH 数据授权，字段中的医院／科室也不能自行授予取数。账号／任务切换或窗口重载使旧绑定和在途结果失效，重连读取当前修订，未提交副本须核对冲突后再继续。EMR 不可用时，DSH 保留独立 AI／参考能力，完整手工编辑明确不可用；不得为兜底复制一套编辑器。

## EMR 兼容约束
